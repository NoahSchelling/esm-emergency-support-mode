# app：スマートフォン向けの簡易な画面（試作）

`modules/` のモジュールを組み合わせて 1 枚の画面に見せるための、簡易なフロントエンドです。見た目の作り込みはしていません。

## 公的情報を優先してください

！！仮の値！！ この画面は、気象庁などの公的な発表を中継し、端末の状態を見せるだけの試作です。独自の予報・警報は出しません。避難や身の安全にかかわる判断は、気象庁・自治体などの公的な発表と指示を優先してください。表示は、古い・止まっている・間違っている可能性があります。

## 画面の作り（2026-11-07 の作り直し、`shell/`・`handoff/`）

- **ライトの表示だけ**です。端末がダークの設定でもライトになります（テーマの切り替えはなくしました。前に保存した選択は読み捨てます）。
- **外枠（幅 10px）とメニューのボタンは常に表示**します（上の帯は画面の上に固定）。
- **メイン画面**：避難者の表示（矢印と避難方向）が中心です。その下に「標高と予想される津波の高さ」と、地図アプリへのリンクを出します（下の表）。
- **サブ画面 1（現在の警戒情報）**：画面の**中ほど**で左右にスワイプ（幅の 15〜85% の範囲で始まり、横に 60px 以上）するか、左右の端の中央の半透明の灰色の「◀」「▶」（背景とのコントラスト 3:1 以上）を押すと切り替わります。画面の端から始まるスワイプは、OS の「戻る」と衝突するため使いません。発表の種類・対象地域・受信時刻を文字で出し、受け取れないときは「警報が出ていないという意味ではありません」と出します。デモの再生の操作もここにあります。
- **上の知らせ**：新しい公的発表を受けると、画面の上に「新しい情報：…」を出します（`role="alert"` で読み上げ）。閉じるまで消えません。同じ地域の新しい知らせは古い知らせを置き換え、最大 3 件まで表示します。
- **外枠の色**：平時は背景色。注意報＝黄、警報＝赤、危険警報＝紫、特別警報・大津波警報＝紫で 3 秒周期のフェード。切迫＝1 秒周期・フェードなしの点滅。切迫は、津波警報の中で**国の津波浸水想定の区域の中**にいるとき。区域が分からない（データがない・同意がない）ときだけ、海岸線から 1000m 以内（！！仮の値！！）を目安にし、「このアプリの目安です。公的な基準ではありません」と出します。決め方は [docs/proto/alert.md](../docs/proto/alert.md)。

### メイン画面の「標高と予想される津波の高さ」

| 行 | 中身 |
| --- | --- |
| 予想される津波の高さ | 最寄りの津波予報区の値。気象庁の津波警報・注意報の電文の `Item/MaxHeight` を試作 C-A がそのまま中継したもの（`proto/c-a/server.py` の `parse_max_height`）。デモの福島県は 2011 年の記録（3m→6m→10m以上）、静岡県は模擬（3m→6m→10m以上、模擬と明記） |
| いる場所の標高 | 国土地理院の標高 API。位置が伝わるので、メニューの「事前情報収集」で同意した後だけ取得します。デモの地点は 2026-11-07 に調べた値をデータに入れています |
| 避難場所の地面の標高 | 国土地理院の標高 API。避難場所の座標は公開されているので、同意なしで取得します（いる場所の位置は送りません）。**地面の高さ**で、避難タワーやビルの上の階の高さは含みません |
| ⚠ | 標高が予想の高さ**以下**（同じ高さも含む）か、予想に上限がない（「10m以上」「巨大」など）とき |
| いつも出す文 | 「地形によって津波は予想より高くなる可能性があります。」「安全」とは書きません |

- **地図アプリの経路**：「この避難場所まで地図アプリで経路を見る」は、Google マップの公式の URL の形式（`https://www.google.com/maps/dir/?api=1&destination=緯度,経度&travelmode=walking`）で、API キーなし、目的地＝避難場所の座標だけを渡します。すぐ下に「地図アプリの経路は、通れない道や浸水を考えていません」を出します。背景の地図は使いません。

### 引き継ぎメモ（`handoff/`）

- メイン画面の下の「Claude に相談する（引き継ぎメモを作る）」で開きます。発災からの時間が `modules/mode/` の段階（発災直後→安全確保後→サバイバル…）に沿って進むほど、ボタンが大きく目立つようになります（安全確保後で中、サバイバル以降で最大）。自動では移りません。
  - 発災の時刻：現在位置のモードでは、情報履歴の中で最初に受けた警報（レベル 3 以上）の受信時刻。デモの記録では記録の時刻、静岡県の模擬では模擬の経過時間。
- アプリが下書きを自動で埋めます：発災からの時間、受信した公的発表（情報履歴から）、向かった避難場所、標高と予想される津波の高さ、電池・通信。**位置の座標は入れません。** 先頭に、Skill がない人のための短い指示文（Claude へのお願い）を付けます。
- 「コピー」「ダウンロード（.md）」「内容削除」「自動の部分を作り直す」。
- 手で直した下書きは、入力のたびにこの端末に保存し、開き直したときに戻します。「内容削除」で保存も消します。画面に「この下書きはこの端末に保存されます。人に渡す前や、不要になったら『内容削除』を押してください」と出します。
- 自動の部分は印（HTML のコメント）で囲み、「自動の部分を作り直す」で情報履歴と現在の値から作り直します（手で書いた部分は残ります）。
- Claude の Skill：[skills/handoff-interview/](../skills/handoff-interview/README.md)。

### 位置の送り先（同意の後だけ）

位置を URL や通信に載せないのが原則です。例外は、メニューの「事前情報収集」で同意した後の次の 2 つだけです。

- 国土地理院の標高 API（`cyberjapandata2.gsi.go.jp`）：いる場所の緯度・経度を送る。
- ハザードマップポータルサイトの津波浸水想定のタイル（`disaportaldata.gsi.go.jp`）：いる場所のまわりの地図の画像を取りに行く（およその位置が伝わる）。画像の中のその地点の色の有無だけを読みます。色あり＝区域の中、透明＝区域の外、タイルなし＝分からない（距離の目安に戻る）。
- どちらも約 50m の範囲ごとに 1 回だけ取りに行き、結果を画面の中だけで覚えます。

## 避難者と支援者の切り替え

メニューの「避難者／支援者の切り替え」にあります。**既定は避難者**です。「支援者」を押すと、下の「画面に出すもの」の試作の画面（これまでの画面）になります。自動では切り替わりません（模擬の発表を受けても切り替えません）。

### 避難者の表示（`evac/`）

通信が細い発災後を想定して、地図は使わず、矢印・距離・名前だけを出します。入力欄はありません。

| 出すもの | 中身 |
| --- | --- |
| 公的情報の優先 | 「公的な発表と指示を優先してください。」（BW-S2） |
| 一言の指示 | 模擬のシナリオのときだけ。この回は「津波の模擬」だけ（`?sim=tsunami`、または支援者の画面の「模擬：津波警報」系のボタン）。模擬の発表の文の引用の形で出し、必ず「【模擬】」と「気象庁・市町村の発表ではありません」を付ける。支援者の画面の「模擬：津波警報の解除を受けた」で、方向の表示をやめる |
| 矢印 | 端末の方位が使えるときだけ。公的に指定された避難場所（指定緊急避難場所）への**直線の方向**。方位が取れない・古い・精度が悪い（Android では、歩いて GPS の進行方向と照らし合わせる前）・揺れている・端末が傾いている・画面が横向き・位置が古いときは、矢印を出さず「北から○度の方向」の文と、北を上にした図（矢印ではなく、円の上の点と破線。「端末の向きとは関係ありません」と添える）にする |

| 「直線の方向です。道順ではありません。」 | 常に表示 |
| 「この方向は通れない」 | 押すと、その方向の前後 30 度と、そのとき示していた避難場所を、10 分（どちらも ！！仮の値！！）除外して次の候補を出す。除外を一覧に出し、「取り消す」で戻せる。判断は利用者のもの |
| 「位置と方位を使う」 | 押したときに、位置と（iPhone では）向きの許可を求める |
| 公的情報の受信時刻 | 「公的情報の受信：○分前」。受信がないときは「受信していません（新しい発表がないという意味ではありません）」 |
| 「端末が強い衝撃を検知しました」 | 表示の場所だけ。検知は次の回（既定では隠している） |
| ほかの候補 | 近い順に 2 件まで（文だけ） |
| 確かめる先 | 災害の種別がない・データを読めない・候補がないときに、地理院地図と民間のサイト（「公的な発表ではありません」と添える）へのリンク |
| このデータについて（たためる） | 国土地理院の「ご利用上の注意」、「市町村が登録し、公開に同意した場所だけが含まれる」、データの更新日、出典 |

- 災害の種別は、この画面では決めません。模擬のシナリオ（または今後つなぐ公的な発表）からだけ受け取ります。ないときは避難場所を選びません。
- 緑色、「安全」「正常」の表示は使いません（BW-S3）。
- 位置は画面の中だけで使い、送りません。緯度・経度は出しません（ただし、避難場所の名前と距離・方位から、およその位置は分かります）。

- `evac/evac-main.js` は `main.js` とは別に読み込みます。支援者の画面のモジュールが読み込めなくても、避難者の表示は動きます。
- Android の Chrome では、向きのセンサーに北を基準にした `deviceorientationabsolute` を使います（支援者の画面の「向き」も同じ。ふつうの `deviceorientation` は北を基準にしていないため）。

## 動かし方

Node.js（22 で確認）だけで動きます。追加のインストールは要りません。リポジトリの一番上で：

```bash
node app/serve.js
```

ブラウザで `http://127.0.0.1:8080/app/` を開きます。試作 C-A のサーバーがないので、公的発表の欄は模擬データになります。

### 試作 C-A のサーバーとつなぐ

C-A を別のポートで起動し、`--ca` でその場所を渡します。

```bash
python3 proto/c-a/server.py --port 8000
```

```bash
node app/serve.js --ca http://127.0.0.1:8000
```

- 画面は同じサイトの `/api/ca/status` を読み、`serve.js` がそれを C-A の `/api/status` に取り次ぎます（C-A に CORS の設定がないため）。取り次ぐのは決まった GET だけで、画面の位置・入力・センサーの値は送りません。
- C-A 自身が模擬データで動いているとき（`--source mock` や、取得に失敗して切り替わったとき）も、画面は「模擬データ」と出します。
- いったん C-A から受け取ったあとに受け取れなくなったときは、模擬データに切り替えず「受け取れていません」（古い）と出します。本物の途絶を隠さないためです。

### `serve.js` のオプション

| オプション | 既定値 | 意味 |
| --- | --- | --- |
| `--port` | 8080 | 待ち受けるポート |
| `--host` | `127.0.0.1` | 待ち受けるアドレス。既定では自分のパソコンからしか見えない |
| `--ca` | なし | 試作 C-A のサーバーの場所 |

配るのは `app/` と `modules/` の中だけです。`python3 -m http.server` でリポジトリの一番上を配っても動きます（そのときは C-A につながらず、模擬データになります）。

### スマートフォンの実機で開くとき

位置・揺れ・向きは HTTPS でないと使えません（HTTP の LAN のアドレスで開くと「使えない（HTTPS ではない）」と出ます）。実機向けの HTTPS の配信の方法は決まっていません（！！仮の値！！）。実機で確かめる点は [docs/proto/app.md](../docs/proto/app.md)。

## 守っていること

- **BW-S1**：独自の予報・警報は出しません。C-A の電文は受け取ったまま出します。C-A の電文は、まだモードの入力につないでいません（電文の種類とモードの対応は未決：！！仮の値！！）。モードを動かすのは、申告のボタンと、`source: "simulated"` の模擬のボタンだけです。
- **BW-S2**：画面のいちばん上に公的情報の優先を出します。
- **BW-S3**：取れない・判定できないを「異常なし」「安全」と出しません。緑色や「正常」の表示を使いません（取れたは青、取れないは橙、古いは赤、未実装は灰）。「平常」には「安全という意味ではありません」を添えます。段階の名前「安全確保後」にも「安全になったという意味ではありません」を添えます。
- **BW-S4**：助言の処理はありません。助言をしない方針を画面に出します。
- 位置は画面の中だけで使います。読み込むのは同じサイトの区域のデータだけで、位置を送る通信はありません。画面に緯度・経度は出しません。
- 揺れと向きの許可は「揺れと向きの許可を求める」ボタンを押したときに求めます（iPhone の Safari のため）。位置の許可も「位置を取って区域を引く」ボタンを押したときに出ます。
- 外部ライブラリは使いません。外部から読み込むものもありません。

## モジュールがないとき

モジュールを読み込めないと、その欄に「未実装」と出し、ほかの欄は動き続けます。画面の下の「読み込んだモジュール」に、どれを読み込めたかを出します。試すときは `?without=` に名前を並べると、その読み込みを止められます（例：`/app/?without=area,fragment`。名前は `sensors` `area` `mode` `fragment` `advice`）。

## テスト

```bash
node --test 'app/test/*.test.js'
```

- `test/lib.test.js`：画面の部品（状態の表示名、モジュールの読み込み、公的発表のまとめ、モードの扱い、表示の文）。ソースに外部の URL、`innerHTML`、緑色がないことも確かめます。
- `test/browser.test.js`：Playwright（Chromium）があるときだけ動きます。幅 375 と 1200 ピクセル、端末の明るい設定と暗い設定（どちらでも画面はライト）で、横スクロールが出ないことと文字のコントラスト（4.5:1 以上）を確かめます。位置の偽装、揺れのイベントの発火、模擬データ、試作 C-A を模した試験用のサーバー、モジュールがないときの表示の切り替わりを確かめます。環境変数 `APP_SCREENSHOT_DIR` を指定すると、画面の写真をそこに保存します（リポジトリの外を指定してください）。
- `test/shell.test.js`：デモの台本と再生、外枠のレベル（浸水想定を含む）、C-A の電文の読み取り。
