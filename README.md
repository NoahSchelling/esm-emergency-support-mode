# ESM 緊急支援モード（Emergency Support Mode）

## 公的情報を優先してください

このリポジトリの成果物は、気象庁などの公的な発表を中継するだけのものです。独自の予報・警報は出しません。避難や身の安全にかかわる判断は、気象庁・自治体などの公的な発表と指示を優先してください。成果物の表示は、古い・止まっている・間違っている可能性があります。

## 緊急支援モードの考え方

### 理想の姿

緊急支援モードの理想は、災害が起きた瞬間から、避難、避難の後の暮らし、復旧、長い復興の時間まで、一人ひとりのそばで「いま出ている公的な情報」と「次の一歩の手立て」をつなぎ続けることです。揺れや警報の直後には、どちらへ逃げるかを一目で示します。命を守った後は、水・食料・電源・連絡・手続きといった段取りを助け、困っていることを専門家や窓口に正しく伝えられるようにします。

災害は、いつか、どこかで、誰にでも起きます。そのときにどう情報を受け取り、どう動き、どう助けを求めるかは、**誰もが避けては通れない課題**です。

この理想のうち、今回のハッカソンでは、時間とルールの都合で次のものを実装していません（詳しくは下の「次の段階」）。

- 事前の情報収集（地図や自治体の連絡先を前もって端末に集めておく機能）
- 支援者向けの、公的機関の独自情報（RSS など）の受信
- 背景の地図とカーナビのような誘導、アプリ自身の経路の計算、建物の高さを使った判断
- 静岡県以外の区域と避難場所のデータ
- 心のケアと医療の支援（下の理由により、実装しない方針）

### メンタルケアの機能を実装していない理由

緊急支援モードでは、メンタルケア（心のケア）と医療の助言の機能を実装していません。

- ハッカソンのルールで、禁止するプロジェクトの例に「AI メンタルヘルスアドバイザー」と「医療アドバイスを行う AI」が挙げられているため。
- **生命倫理の問題**があるため。災害の中で、機械が人の心や体の状態を判断し、助言することには、誤ったときに取り返しがつかないこと、責任を誰が負うのか、弱っている人の判断を機械が左右してしまうことなど、簡単には答えの出ない問題があります。生命倫理の問題もまた、**誰もが避けては通れない課題**です。

その代わりに、アプリは「伝達メモ」を作り、Claude の Skill（[skills/handoff-interview/](skills/handoff-interview/README.md)）が、一度に一つずつ短く聞き取って、医師・保健師・自治体の窓口などの専門家に見せられる形にまとめます。段取りと情報の支援はしますが、医療・心の診断や助言はせず、119・#7119・自治体の相談窓口につなぐことを優先します（CLAUDE.md の BW-S4）。

### このシステムが目指すもの

災害において、解決が難しい問題は山のようにあります。この試作も、そのごく一部にしか手が届いていません。

それでも、緊急支援モードは、

- **一人でも多くの人を助けようと支援するシステム**であり、
- **今後も育ち続けるシステム**であり、
- **被害をゼロにするのではなく、緩和していくシステム**です。

## 画面の使い方（2026-11-07 の作り直し）

エリアメールを受け取ってこの画面を開く人は、落ち着いて文章を読めないことを前提にしています。文字は少なく、図と記号で次の行動が分かるようにしています（見た目は Bento Grid 風のカード）。

- 画面はライトの表示だけです（端末がダークの設定でもライト）。上の帯「ESM 緊急支援モード」はスクロールで隠れ、避難の情報を優先して見せます。右上のハンバーガーメニューは常に表示します。
- **一行の情報**：方位の図の上に、いちばん大事な情報を一行だけ出します（優先は 津波＞地震＞その他の災害）。新しい情報は画面の右端から定位置へスライドして入ります。1 位でなくなった情報は、方位の図の下へ移ります。日時は年を省き「3.11 14:46」の形です。
  - 津波：`大津波警報 10m以上、静岡県、予想`（発表の種類・高さ・地域または観測点・到着時刻・予想／実測。分からない項目は省きます）
  - 地震：`地震 最大震度〇、〇〇県〇〇地域、M〇、深さ〇km、予想／実測`（公的な発表の値だけ。端末の揺れは震度と呼びません）
  - 受け取っている発表がないとき：「身の安全を確保してください」。受け取れないときは、そう書きます。
- **方位の図（ヘディングアップ）**：向いている方角と避難目標を、大きく同じ位置に出します。上向きの黒い ▲ は「スマートフォンが向いている方向」で固定し、方角の円（北・東・南・西）と避難目標の印（オレンジの「避」）が、0.3 秒の滑らかな動きで回り続けます（向きはセンサーから読むだけで、通信はしません）。向きを確かめられないときは、北を上にした図で、避難場所を点と点線で示し（上向きの矢印は出しません）、図の下に「北が上の図です（方位を確かめられないため）。」と出します。その下に**現在地の標高**（約〇m）を常に出します。標高が津波の高さ以下なら「⚠️津波よりも下にいます」、津波の高さに上限がない（「10m以上」など）なら「⚠️津波上限が予測不能です」と出します。津波の高さは、**予想と実測（観測された高さ）の高いほう**と比べます。津波が観測されてから届くまでには、まだ避難できる時間があり、避難をあきらめさせないためです。津波の発表が出ている間は「津波は予想より高くなる場合あり。」と出します。どの場合も「安全」とは書きません。観測された津波の行と画面の外枠も、高さに応じて色分けします（発表の色と比べて高いほう。CLAUDE.md の BW-S1 の例外）。使う観測値は、その区域に津波の発表が出ていて、その発表より後に観測されたものだけです（気象庁が警報を下げた後は、古い観測で外枠を上げません）。
- 小さな文字の説明は、要約だけを見せて折り畳んでいます（行頭の「▶」を押すと開きます）。
- デモに関する表示は、画面のいちばん下の「デモモードの情報」（黒い枠の箱）にまとめています。デモの間は、一行の情報にも「模擬」「記録の再生」の印を付けます。
- 画面の中ほどで左右にスワイプするか、左右の端の「◀」「▶」を押すと、**現在の警戒情報**（発表の種類・対象地域・受信時刻）の画面に切り替わります。
- 新しい情報が入ると、画面の上に「情報が更新されました」とだけ出し、2 秒で閉じます（読み上げに対応）。中身は、すぐ下の一行の情報で分かるようにしています。観測された津波の高さで外枠のレベルが上がったときは、「気象庁の観測値による色枠表示」を 2 秒出します。
- 「この方向は通れない」（現在地の標高の下）を押すと、方位の図の外周にその方向の × を出し、次の候補を示します。× は方位の円と一緒に回ります。その下の「▶現在通れない方向」を開くと、時刻・方位・「取り消し」が並びます。手で消さなくても 10 分で自動で取り消します。
- 「位置と方位を使う」はトグルスイッチです（ON で使い始め、OFF でやめる）。
- 「地図で避難目標を見る」は、国土地理院の地図（地理院地図）を、避難場所の公開された座標を中心に開きます（ズーム 15。いる場所は渡しません）。道順は出しません（下の「道順の機能を入れていない理由」）。「確かめる先」の民間のサイトには、名前の横に「（民間）」と出します。
- 「Claude に相談する（伝達メモを作る）」は、発災から時間がたつ（サバイバルの段階に近づく）ほど目立つようになります。自動では画面は移りません。
- メニュー：事前情報収集（位置を外に送る取得への同意）／避難者・支援者の切り替え／これまでの情報履歴／記録の出典／公的機関のウェブサイトリンク／公的機関の連絡先／独自情報の情報取得URL（次の段階）／デモモード。各項目は行頭の「▶」「▼」で開閉が分かります。二択はラジオボタン（押すとすぐに切り替わる）、デモの ON／OFF はトグルスイッチ、場所はドロップダウンリストです。
- 詳しくは [app/README.md](app/README.md)。

## 簡易な動作検証方法

ご自分のスマートフォンで試す方法です。公的情報を優先してください。この画面は試作で、公式の発表ではありません。

### いちばん簡単な方法：デモを開く

- URL：https://（公開先の URL）/app/?demo=shizuoka
- 静岡県の模擬と、福島県・千葉県・東京都の過去の記録の再生を、右上のメニューから選べます。
- 公的な発表は受け取りません。画面には「受け取れていません」と「模擬データ」の表示が出ます。
- 「位置と方位を使う」を ON にすると、方位の図と GPS の確かめに端末のセンサーを使います。位置はデモの地点のままで、外には送りません。
- 置き場所は、GitHub Pages のような静的な公開先で足ります（HTTPS で開けること）。

### 本物の発表も受け取る方法：サーバーに置く（例：Amazon EC2）

構成：スマートフォン → Caddy（HTTPS、443 番）→ `app/serve.js`（127.0.0.1:8080）→ 試作 C-A（127.0.0.1:8000）→ 気象庁の XML フィード

1. Linux のインスタンスを 1 台用意します（小さいもので足ります）。セキュリティグループで開けるのは 80 番と 443 番だけにし、SSH は自分の接続元に絞ります。
2. ドメイン名をインスタンスのアドレスに向けます。スマートフォンのブラウザは、HTTPS で開いたページにしか位置と方位を渡しません。
3. Node.js（18 以上）と Python 3 を入れ、このリポジトリを取得します。
4. 2 つを起動します（どちらも 127.0.0.1 で待ち受け、外からは直接見えません）。
   - `python3 proto/c-a/server.py --source live`
   - `node app/serve.js --ca http://127.0.0.1:8000`
5. Caddy を入れ、次の設定で起動します（証明書は自動で取得されます）。
   - `（ドメイン名） { reverse_proxy 127.0.0.1:8080 }`
6. スマートフォンで https://（ドメイン名）/app/ を開きます。

注意：

- 試作 C-A の `--demo` は付けないでください（画面から模擬の警報を入れられるため）。
- 気象庁への取得は 60 秒に 1 回です。間隔を短くしないでください。
- 発表から画面に出るまで、最大 1〜2 分ほどかかります。画面を開いている間だけ取りに行きます。
- 位置はサーバーに送りません。サーバーの記録に残るのは、ふつうのアクセス記録（接続元のアドレスなど）だけです。標高と浸水想定は、同意した後に端末から国土地理院へ直接問い合わせます。
- 審査が終わったら、インスタンスを止めてください。

## プライバシー（位置の扱い）

- いる場所（緯度・経度）は、端末の中だけで使います。URL や通信に載せません。避難場所への方向・距離、区域の判定、方位の計算は、すべて端末の中で行います。
- **例外は 2 つだけ**で、どちらもメニューの「事前情報収集」で同意した後だけ行います。
  - **標高**：国土地理院の標高 API に、いる場所の緯度・経度を送り、その地点の標高を受け取ります。
  - **浸水想定**：ハザードマップポータルサイト（国土地理院）の津波浸水想定の地図の画像を、いる場所のまわりについて受け取ります（画像の番号から、およその位置が伝わります）。
- 同意しなければ、この 2 つは行いません。そのときは標高を「調べていません」と出し、切迫の判断は海岸線からの距離（このアプリの目安）で行います。
- **止め方**：メニューの「事前情報収集」で「同意しない」を選ぶと、すぐに止まります。同意の記録は端末に保存しており、「同意しない」を選ぶと消えます。
- 避難場所の座標（公開されたデータ）は、地図のリンクと避難場所の標高の取得に使います。いる場所は含みません。
- 伝達メモの下書きには、位置の座標を入れません。

## 既知の限界

- **水害（洪水・内水・高潮）の避難誘導は、意図的に入れていません。** 方位の図と避難目標は、津波の発表があるときだけ出します。水害は津波と水の流れ方が異なり（川や低い土地に沿って、時間をかけて広がるなど）、直線の方向の矢印が、かえって危険な方向を示しうるためです。
- 方向は直線です。道順ではなく、通れるかどうかも判断していません。
- 方位の精度を確かめられないとき（Android は精度の値を出さないので、立ち止まっている間など）は、北を上にした図にします。間違った方向を示すくらいなら、回さないという判断です。ただしデモでは、位置がデモの地点に固定されていて矢印が人を導くことはないため、この確かめを省き、回る図のままにします。スマートフォンを回している間（4 秒まで）も、回る図のままにします。
- 区域データと避難場所のデータは静岡県だけです。試作 C-A は、地震と津波の観測の電文をまだ読みません（地震の行と実測の比較はデモだけで動きます）。
- 実機と、本物の R06 形式の電文では、まだ十分に確かめていません。

## 道順の機能を入れていない理由

- 一般のナビ（地図アプリの徒歩の道順）は津波を考えません。近道として、海沿いの大通りを案内することがありえます。
- そのため、地図のリンクは避難場所を中心に地図を開くだけにし、道順は出しません。
- 等高線のある地理院地図を使った誘導（高いほうへ向かう道を選べるようにする）は、次の段階で実装する予定です。

## 次の段階（今回は実装していないもの）

- **事前情報収集**：画面とデータの端末への保存（オフラインで開ける）、ON／OFF のトグル、収集済みデータの削除ボタン。GPS の周辺の地図、自治体の連絡先の事前収集。
- **支援者のサブ画面 2**：公的機関の独自情報（RSS など）の受信。登録先は `go.jp`・`lg.jp` などに限り、取得は `app/serve.js` の取り次ぎで、https・大きさと時間の上限付きにする。
- 等高線のある地理院地図を使った誘導、背景の地図、自前の経路計算、建物の高さのデータ（PLATEAU）を使った避難タワー・ビルの高さの表示（いまは避難場所の「地面の標高」だけで、タワーやビルの上の階の高さを含みません）。
- 静岡県以外の区域データと避難場所のデータ。
- 本物の R06 形式の気象庁の電文（津波警報の予想の高さを含む）での確かめ。実機（Android の Chrome、iPhone の Safari）での確かめ。
- 伝達メモの自動の部分の拡充（避難所の情報、受け取った避難指示など）。

## モジュール

- 区域の判定（緯度・経度から、市町村と気象庁の警報・注意報の区域のコードを端末の中で引く。静岡県のみ）：[modules/area/README.md](modules/area/README.md)。区域を引くだけで、警報の有無は判定しません。「判定できない」は「安全」ではありません。
- 緊急支援モードの状態機械（平常／警戒高め／緊急と、緊急の中の段階）：[modules/mode/README.md](modules/mode/README.md)。入力は公的な発表と利用者の申告だけで、独自の判断はしません。「平常」は「安全」という意味ではありません。規則どうしの衝突と未決事項は [docs/proto/mode.md](docs/proto/mode.md)。
- 避難場所への直線の方向（国土地理院の指定緊急避難場所データから、災害の種別に対応した避難場所の近い順の候補と、直線距離・真北からの方位を端末の中で求める。静岡県のみ）：[modules/evac/README.md](modules/evac/README.md)。道順ではありません。安全かどうか、通れるかどうかは判断しません。データには市町村が登録し公開に同意した場所だけが含まれ、欠けがありえます。実機で確かめる点は [docs/proto/evac.md](docs/proto/evac.md)。
- 外枠のレベル（公的発表の種類を色にし、津波警報の中で国の津波浸水想定の区域の中にいるとき（区域が分からないときは、このアプリの目安として海岸線からの距離）は速く点滅させる）：[modules/alert/README.md](modules/alert/README.md)。独自の予報・警報は出しません。色がないことは安全という意味ではありません。メニューとデモモード（静岡県の模擬、福島県・千葉県・東京都の過去の記録の再生）は [docs/proto/alert.md](docs/proto/alert.md)。

## 開発に参加する人へ

このリポジトリは、認証情報と個人情報が入らないように、コミットとプッシュのたびに検査します。クローンしたら、最初に次を実行して Git のフックを有効にしてください（Git の仕組み上、クローンしただけではフックは動きません）。

```bash
git config core.hooksPath .githooks
```

- 必要なもの：bash 4.4 以上と git。macOS に最初から入っている bash は 3.2 なので、Homebrew などで新しい bash を入れてください。python3 があると、検査の一部（表記ゆれ、符号化した値）が強くなります。
- 個人語（本名など）の検査には、リポジトリの外に置いた禁止語ファイルを環境変数 `ESM_DENYLIST_FILE` で指定します。書き方と仕組みの詳細は [CLAUDE.md](CLAUDE.md) の「開発基盤」にあります。
- 検査のテスト：`bash tests/check-secrets.test.sh`
- 公開前の最終確認（全履歴・すべてのブランチとタグ）：`scripts/check-secrets.sh --all --require-denylist`
