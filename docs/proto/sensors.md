# センサーのモジュール：実機で確かめるべき点

- 作成日：2026-11-05（日本時間）
- 対象：`modules/sensors/`（使い方は [modules/sensors/README.md](../../modules/sensors/README.md)）
- 状態：**実機では未確認**。この回は仮想マシンの中だけで作業したため、自動テスト（再生のデータ）と Playwright の Chromium（偽装した位置と、スクリプトで発火したイベント）でしか確かめていません。

## 1. 仮想マシンの中で確かめたこと

| 確かめたこと | どうやって |
| --- | --- |
| 6 つのモジュールが、結果の共通の形を守る | `node --test`。再生のデータを全モジュールに流し、毎秒すべての結果を検査 |
| `value` は `ok` のときだけ入る | 同上 |
| 値が止まると `stale` になり、秒数を引数で変えられる | 同上（再生のデータに 45〜52 秒の空白を入れてある） |
| 揺れの最大値（期間・記録）、期間内に値がないときは `unknown` | 同上 |
| iPhone の Safari を模した許可（`requestPermission()` を呼ぶまでイベントが届かない） | 再生の環境で模擬 |
| 許可を求める関数が、ブラウザの API を同期的に呼ぶ（間に await がない） | テストで確認 |
| 位置の偽装で、緯度・経度・誤差が取れる | Playwright（Chromium） |
| `DeviceMotionEvent` と `DeviceOrientationEvent` を発火して値が取れる | Playwright（Chromium） |
| オフラインに切り替えると通知が来る | Playwright（Chromium） |
| 許可がないと `denied`（位置）、`denied` か `unknown`（揺れ・向き） | Playwright（Chromium） |
| HTTP の LAN アドレスで開くと、6 つすべてが `insecure` | Playwright（Chromium） |

Playwright のイベントは、スクリプトで作った偽物です。本物のセンサーの値の出方（頻度、単位、座標軸の向き、空の値の出し方）は確かめていません。

## 2. 実機で確かめるべき点

### 共通

- [ ] HTTPS で配信して開けるか（実機では `localhost` が使えない。HTTPS の配信の方法は未定：！！仮の値！！）。
- [ ] HTTP で開いたとき、6 つとも `insecure` になるか。
- [ ] 画面を裏に回したとき・画面を消したとき・戻したときに、揺れと向きが `stale` になり、戻ると `ok` に戻るか。位置の更新が止まるか。
- [ ] 既定の秒数（揺れと向きは 2 秒、位置は 120 秒、位置の取得の待ち時間は 30 秒。すべて！！仮の値！！）が実際の更新の間隔に合っているか。
- [ ] `observed_at` のタイムゾーンが端末の設定どおり（日本なら `+09:00`）か。

### iPhone の Safari

- [ ] 「揺れと向きの許可を求める」ボタンで、許可を求める画面が出るか。揺れと向きで 1 回ずつ出るか、まとめて 1 回か。
- [ ] ボタンを押さずに `requestPermission()` を呼んだとき（ページを開いた直後など）、何が返るか（`NotAllowedError` で `error` になるか、`"prompt"` で `unknown` になるか）。
- [ ] 許可しなかったあと、もう一度ボタンを押すと何が返るか。もう一度求めるには何が要るか（ページの再読み込み、Safari の再起動、設定）。いま `detail` には「ブラウザを開き直すか、設定を変える必要がある場合がある」と書いている。正しいかを確かめ、文言を直す。
- [ ] `webkitCompassHeading` と `webkitCompassAccuracy` が入るか。
- [ ] 通信の種類と電池が `unsupported` になるか（Safari にはこの 2 つの機能がない想定）。
- [ ] ホーム画面に追加して開いたときも、同じように動くか。
- [ ] 位置の許可を「1 回だけ許可」にしたとき、次に開いたときの挙動。

### Android の Chrome

- [ ] 許可を求める画面なしで、揺れと向きの値が届くか（`requestPermission()` が `not_required` か `granted` を返すか。仮想マシンの Chromium は `requestPermission()` を持っていて、許可がないと `"prompt"` か `"denied"` を返した）。
- [ ] 揺れのイベントの間隔（`interval_ms`）と、1 秒あたりの回数。
- [ ] `acceleration`（重力を除く）が null の端末があるか。そのとき最大値の表示がどうなるか。
- [ ] 通信の種類で `type`（wifi、cellular など）が入るか、`effective_type` だけか。Wi-Fi と携帯回線を切り替えたとき、`change` の通知が来るか。
- [ ] 電池の値と、充電の抜き差しで通知が来るか。
- [ ] `deviceorientationabsolute`（`eventName` で指定）で、北を基準にした値が取れるか。

### 揺れ（BW-S1 にかかわる）

- [ ] 机に置いたまま、手に持って歩く、ポケットに入れる、のそれぞれで、値がどのくらい動くかを記録する（`recorder.js` で記録。位置は含めない）。**この記録を、地震の判定の材料にはしない。** 値の見せ方と、「震度ではありません」の説明が誤解を生まないかを確かめるため。
- [ ] 画面に出したとき、利用者が「震度」や「地震の大きさ」と受け取らないか（表示の言葉は「この端末が記録した揺れ（震度ではありません）」）。

### 通信の有無

- [ ] 機内モードにしたとき、`offline` の通知が来るか。戻したとき `online` が来るか。
- [ ] Wi-Fi にはつながっているがインターネットに出られないとき、`online: true` のままになるか（想定どおりなら、画面で「届くとは限らない」と出す理由になる）。

### 位置

- [ ] 屋内・屋外で、誤差（`accuracy_m`）がどのくらいか。
- [ ] 位置の許可を断ったときに `denied`、端末の位置情報をオフにしたときに何が返るか（`denied` か `error` か）。
- [ ] 実機で確かめるとき、**実際の位置を記録・コミットしない**。画面の写真を撮るときも、位置の値が写らないようにする。

## 3. 実機の記録を再生に使うとき

1. 試験用のページで「生の値の記録を始める（位置は含めない）」を押し、操作し、「記録を止めて保存する」で JSON を保存する。
2. 中身を確かめる（位置が入っていないこと）。
3. 必要なら `modules/sensors/fixtures/` に置いてテストに使う。置く前に、検査スクリプトを通す。
