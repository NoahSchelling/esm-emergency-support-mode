# 試作：助言の入口（modules/advice）

- 作成日：2026-11-05（日本時間）
- 置き場所：`modules/advice/`（使い方は [modules/advice/README.md](../../modules/advice/README.md)）
- 状態：**インターフェースのみ**。助言の処理は実装していない。

## 1. 位置づけ

CLAUDE.md の BW-S4 は、メンタルヘルスの助言と医療の助言に当たる処理を実装しないこと、成果物でこの方針に言及すること、将来の追加に備えたインターフェースだけを用意することを求めている。`modules/advice/` はその「インターフェースだけ」に当たる。

- 既定の門は提供元を持たず、すべて `unsupported` を返す。
- `modules/fragment/` はこのモジュールを呼ばない（テストで確かめている）。利用者の入力の文面、位置、断片の解析結果は、門に渡さない。提供元が受け取るのは `topic` だけ。
- 成果物でのこの方針への言及：`modules/advice/README.md`、`modules/fragment/README.md`。画面ができたら、画面にも同じ趣旨を書く。

## 2. 設計の理由

| 選んだこと | 理由 |
| --- | --- |
| 提供元は既定で空。足すには呼び出し側が明示的に渡す | 黙って有効になることを防ぐ |
| 提供元の結果は門で検査し、外れたら `error` に置き換える | 提供元が共通の形、出どころ、公的情報の優先、安全の言い切りの禁止（BW-S1〜S3）を破っても、画面に出ないようにする |
| `source` に `jma` `user` `device` を許さない | 助言を公的発表や利用者の申告に見せかけない |
| 提供元に `topic` だけを渡す | 位置などの個人の情報、入力の文面を端末の外へ出す経路にしない |
| 方針の説明文に、行動の指示を入れない | 説明文自体が助言にならないようにする。避難などは公的な発表と指示の優先とだけ書く |

## 3. 将来、提供元を足すときの手順

1. **先に設計を見直す**。助言の内容を誰が責任を持って決めるか（専門家の監修の有無）、対象の範囲、出さない場合（取れない、判定できない）の見せ方を決める。実装はその後。
2. 提供元が受け取る情報を `topic` から増やすときは、端末の外へ出る情報がないか確かめる（位置などの個人の情報は出さない）。
3. 画面では、助言を公的な発表と区別して出す（`notAnnouncement`）。公的情報を優先する旨を、助言の近くに常に出す。
4. 「助言が出ない」ときの表示を決める。出ないことを、問題がない、安全、という意味にしない（BW-S3）。
5. テストを足す。門の検査の項目が、新しい提供元でも効いていること。
6. README と開発ログに、足したこと、監修の有無、試した範囲を書く。

## 4. 見逃しうる誤り

- **門の検査は言葉の一致が中心**。「安全です」を避けて、同じ意味の別の言い方をする提供元は通る。検査を通っても、助言が適切とは限らない。
- 助言の「文面」が公的情報の代わりに見えるかどうかは、画面の作りで決まる。この層では防げない。
- 利用者の入力から心理状態や症状を推し量る処理は、ここにも、解析器にもない。足すなら、それ自体が BW-S4 の対象になる。
- `topic` が 2 つ（`mental-health` `medical`）だけなので、分類に合わない問い合わせは `unsupported` になる。

## 5. まだやっていないこと

- 画面側（`unsupported` の `detail` を出す部分）。
- 提供元の実例。作っていない。
