# 試作 C-B：気象庁の発表文の言い換えと、原文との照合

- 作成日：2026-11-04（日本時間）
- 置き場所：`proto/c-b/`
- 状態：**試作**。本番では使わない。

## 1. 何をするものか

気象庁防災情報 XML の地震情報と気象警報・注意報を、平易な日本語に言い換えます。言い換えが原文の事実から外れていないかを**機械的に照合**し、食い違いが見つかった言い換えは表示しません。画面では、原文と言い換えを並べ、発表時刻を出します。

| 部分 | ファイル | 中身 |
| --- | --- | --- |
| 取得 | `proto/c-b/fetch.py` | 気象庁のフィードから地震情報と気象警報（R06 形式）を選んで取得し、保存する |
| 解析 | `proto/c-b/bulletin.py` | 電文を読み、画面に出す「原文」（言い換えが扱ってよい範囲）を作る |
| 照合器 | `proto/c-b/verifier.py` | 原文の事実を取り出し、言い換え文で同じ事実が保たれているかを確かめる |
| 言い換え | `proto/c-b/paraphrase.py` | 言い換えを作る部分。差し替えられる形にしてある（3 章） |
| 例文 | `proto/c-b/examples.json` | Claude Code が作った言い換えの例。正しい例、わざと誤りを入れた例、照合器が見逃す例 |
| 確認 | `proto/c-b/check_examples.py` | 例文をすべて照合器にかけて結果を出す |
| 画面 | `proto/c-b/server.py`、`proto/c-b/static/` | 原文と言い換えを並べる画面 |
| テスト | `proto/c-b/test_c_b.py` | テスト（21 件） |
| 電文 | `proto/c-b/bulletins/` | 取得して保存した電文 7 件（出典は同じ場所の `README.md`） |

### 安全の下限への対応

- **BW-S1**：言い換えは原文の範囲を越えない。照合器は、予報・推測・助言・程度の判断を表す言葉が原文より増えたら止める（4 章）。運用種別が「通常」以外の電文は、取得の時点で保存せず、照合器も言い換えを止める。警報の種類・地域・状態は、電文の値をそのまま書くことを求める（`docs/research/jma_data.md` の 4.3「言い換えない、まとめ直さない」に合わせた）。
- **BW-S2**：画面の上に、公的な発表を優先する旨を出す（文言は「！！仮の値！！」）。
- **BW-S3**：「安全」「安心」「大丈夫」「心配いりません」などは、原文になくても、言い換えに入っていれば止める。「解除」や「発表警報・注意報はなし」は、電文の言葉のまま書く。緑色など安心を連想させる色は使っていない。照合を通った言い換えにも「正しさを保証するものではない」と書いている。
- **BW-S4**：心理的な助言や医療の助言は扱わない。言い換えを作る指示（プロンプト）にも書き、照合器でもその種の言葉（深呼吸、病院、受診など）を止める。画面の下にもこの方針を書いている。

### 新しい電文を取得する

```bash
python3 proto/c-b/fetch.py --out 作業用のディレクトリ --quakes 2 --warnings 2
```

気象庁の高頻度フィード（地震火山と随時）から、新しい順に地震情報と気象警報（R06 形式）を選んで取得します。`--long-feed` を付けると長期フィード（数日分）から選びます。ファイル名を並べると、その電文だけを取得します（保存した 7 件はこの方法で取得しました）。

```bash
python3 proto/c-b/server.py --bulletins 作業用のディレクトリ
```

で表示できます。新しく取得した電文には例文がないので、「この電文には言い換えの例文がありません」と出て、言い換えは出ません。

- 取得先は `https://www.data.jma.go.jp/developer/xml/` の下（フィードと電文）だけに限っています。電文のファイル名の形と大きさ（2MB まで）も確かめます。
- 運用種別が「通常」以外の電文は保存しません。
- 取得のたびに、取得元の URL・応答の Date ヘッダ・取得時刻を `fetched.json` に書きます。

## 3. 言い換えを作る部分

`proto/c-b/paraphrase.py` に、差し替えられる形で 2 種類を用意しました。どちらも `paraphrase(電文)` を持ち、文字列を返します。**呼ぶ側は必ず照合器にかけてから表示します**（`server.py` がそうしている）。

| 種類 | 中身 |
| --- | --- |
| `ExampleParaphraser` | `examples.json` の例文を返す。この試作の既定。例文は Claude Code が電文を読んで書いた |
| `ApiParaphraser` | 言語モデルの API を呼ぶ形だけ。指示文（`build_prompt`）を組み立て、外から渡された通信の関数（`transport`）に渡す。この試作では `transport` を渡していないので、呼ぶと「API を呼びません」というエラーになる。API キーは読まない |

`build_prompt` の指示には、照合器が求めること（情報の種類をそのまま書く、時刻を「M月D日H時MM分」で書く、数は算用数字で書く、地域と震度・警報は同じ文に書く、付加文はそのまま書く、予報・推測・助言を足さない、心理的な助言や医療の助言を書かない など）を入れています。本物の API につなぐときは、`transport` に通信の関数を渡すだけで、ほかの部分は変えずに済むようにしました。認証情報は `transport` の側で扱い、このリポジトリには置きません。

## 4. 照合器が確かめること

照合器は日本語の意味を理解しません。言い換え文から、時刻・数値・震度・警報の種類と状態・地域名・取消と訂正の言葉・予報や助言の言葉を、**文字の形**で拾い出し、原文の事実と突き合わせます。

まず、全角の数字や記号を半角にそろえ（Unicode の NFKC 正規化）、空白を除きます。迷うときは止める方に倒しています。止めすぎる（正しい言い換えを止める）ことは許し、通しすぎることを避ける方針です。

### 原文の範囲

画面に出す「原文」は、電文の一部を切り出したものです。言い換えはこの範囲だけを扱います。

| 電文 | 原文に入れたもの | 入れなかったもの |
| --- | --- | --- |
| 地震（震度速報、震源に関する情報、震源・震度に関する情報） | 情報の種類、情報の形態（発表・訂正・取消）、発表時刻、見出し、発生時刻、震央地名、位置と深さ、規模、最大震度、都道府県と細分区域ごとの最大震度、固定付加文 | 市町村と観測点ごとの震度、観測点についての付加文 |
| 気象警報・注意報（R06 形式） | 情報の種類、情報の形態、発表時刻、見出し、府県予報区と一次細分区域ごとの警報・注意報の種類・状態・付加事項 | 市町村ごとの状態、時系列の予想（風の強さ、危険度など） |

時系列の予想を入れなかったのは、予想の値を言い換えで扱うと、BW-S1（独自の予報を出さない）との境目が曖昧になるためです。

### 確かめる項目

| 確認 | 止める場合 |
| --- | --- |
| 運用種別 | 電文の運用種別が「通常」でない |
| 禁止語 | 「安全」「安心」「大丈夫」や、心理・医療の言葉がある（BW-S3、BW-S4） |
| 付け足し | 予報・推測・助言・程度の判断の言葉（「注意して」「おそれ」「今後」「ください」「強い」「小さ」「約」「きょう」など）が、原文での回数より多い（BW-S1） |
| 否定 | 打ち消しの言い回し（「ません」「ない」など）が、原文での回数より多い |
| 時刻の書き方／漢数字 | 「14:50」のような書き方や、漢数字の時刻・数がある（照合できないので止める） |
| 取消・訂正 | 原文が取消（訂正）なのに、その言葉がない。原文が発表なのに、取消・訂正の言葉がある |
| 情報の種類 | 電文の「情報の種類」（ヘッダの標題）がそのまま書かれていない |
| 時刻 | 原文にない日時がある。発表時刻（地震では発生時刻も）が、日・時・分まで書かれていない。「午後6時」は 18 時として扱う |
| 日付・数値 | 原文にない日付・数値がある |
| 規模・深さ | マグニチュードや深さ（km）の値が違う、または書かれていない |
| 付加文・付加事項 | 地震の固定付加文が、そのままの形で書かれていない。警報の付加事項（突風、ひょう など）がない |
| 地域名（余分） | 原文の範囲の外にある地域名（電文にはあるが画面に出していない市町村や観測点、電文にない都道府県）がある |
| 震央地名 | 「震源」「震央」と同じ区切りに、震央地名が書かれていない、または別の地域名がある |
| 震度 | 原文にない震度がある。最大震度がない。細分区域と震度が同じ文にそろっていない。区切り（読点まで）の中の地域と震度の組み合わせが原文と違う |
| 警報の種類 | 原文にない警報・注意報の名前がある（例：強風注意報 → 暴風警報） |
| 警報の段階 | 種類名の外で「警報」「特別警報」などの言葉が、原文より多い |
| 地域ごとの種類と状態 | 地域・種類・状態（発表・継続・解除など）が同じ文にそろっていない。区切りの中の組み合わせが原文と違う |

### 例文で確かめた結果

保存した 7 件の電文それぞれに、正しい言い換えを 1 つ、わざと誤りを入れた言い換えを 3〜8 個、照合器が見逃すと分かっている言い換えを 0〜4 個作りました（`examples.json`）。

| 種類 | 件数 | 結果 |
| --- | --- | --- |
| 正しい例 | 7 | すべて通過し、画面に出た |
| 誤りの例 | 32 | すべて止めた。例ごとに決めておいた確認で止まった |
| 見逃す例 | 9 | すべて通った（5 章に書いた見逃し） |

誤りの例で確かめた誤りの種類：数値（震度・マグニチュード・深さの単位）、時刻（発生時刻・発表時刻、午後の書き方、漢数字、「14:50」の書き方、「きのう」への置き換え）、地域名（震央の取り違え、地域と震度の入れ替え、地域の抜け、原文にない県名、画面の範囲外の市名）、情報の種類（書き忘れ）、取消・訂正（発表なのに「訂正」と書く）、警報（原文にない警報の追加、注意報から警報への格上げ、状態の反転、状態の打ち消し、地域の入れ替え、付加事項の抜け、段階の言葉の追加）、付加文の反転、予報・助言・判断の追加、「安全です」「もう心配いりません」、心理的な助言。

取消の電文は実物が手に入らなかったので、テストの中だけで、保存した熊本の電文を元に「模擬」の取消電文を作って確かめました（取消の言葉がない言い換えを止める、取り消された内容を書いた言い換えを止める）。

## 5. 照合器が見逃しうる誤りの種類

照合器は文字の形しか見ていません。次のような誤りは見逃します。`examples.json` の「見逃す例」（`known_misses`）で、実際に通ってしまうことを確かめたものには、例の名前を付けました。

### 意味の誤り

- **原文の事実をそのまま残したまま、別の文で反対のことを言う。** 付加文「この地震による津波の心配はありません。」をそのまま書き、続けて「ただし、津波が来ます。」と書いても通る（`Q2-miss-contradiction`）。付加文が「そのままの形であるか」しか見ていないため。
- **値の役割の入れ替え。** 発表時刻と発生時刻を入れ替えても、どちらの時刻も原文にあるので通る（`Q3-miss-time-roles`）。緯度と経度の数値を入れ替えても通る（`Q2-miss-latlon-swap`）。マグニチュードと深さは、それぞれの書き方（「マグニチュード」「km」）で確かめているので止まる。
- **一覧の中に余分な地域を混ぜる。** 「震度2を観測したのは、A、B、C、D です」の一覧に、震度1の地域を足しても、一覧の中のどれか 1 つが震度2なら通る（`Q3-miss-list-extra`）。読点で区切った中に地域と震度が 1 つずつなら止まる。
- **否定や条件の付け方が、一覧にない言い回しのとき。** 「ません」「ない」などは数えているが、「〜でなければ」のような条件の付け方や、一覧にない打ち消しの言い回しは通ることがある（実際には試していない）。
- **程度・確かさの言い換え。** 原文の「ころ」を「ちょうど」に変え、時刻を正確なものとして書いても通る（`Q1-miss-precision`）。一覧にない程度の言葉（「ちょうど」「かなり」など）は見ない。

### 付け足しの誤り（BW-S1・BW-S3）

- **一覧にない言い回しの助言・予測・安心。** 「揺れたら机の下に入るのがよいです」（`Q3-miss-advice-without-keyword`）、「空気はもう湿っています」（`W2-miss-reassurance`）、「北部は穏やかです」（`W3-miss-calm`）は通る。照合器は決まった言葉の一覧（「ください」「ましょう」「おそれ」など）を数えているだけで、意味で判断していない。「安全」と同じことを別の言葉で言う場合も、一覧になければ通る。
- **電文にない地名（都道府県名以外）。** 照合器が知っている地名は、その電文に出てくる地名と、47 都道府県の名前だけ。「東京駅でも揺れました」は通る（`Q3-miss-unknown-place`）。
- **原文の言葉の回数の範囲内での付け足し。** 「注意して」などは原文より多いかどうかで判断しているので、原文に 1 回ある言葉を、別の内容について 1 回だけ使うと通る。

### 照合の前提が崩れる場合

- **原文の切り出しが間違っている場合。** 照合器は `bulletin.py` が作った「原文」と比べるだけ。解析に誤りがあれば、照合器も誤った事実に合わせて通す。
- **原文の範囲の外にある大事な情報。** 市町村ごとの震度・警報や、時系列の予想は、原文にも言い換えにも入らない。言い換えは「原文の範囲」で正しくても、電文全体から見れば情報が欠けている。
- **ほかの電文との関係。** 照合器は 1 件の電文と 1 つの言い換えを比べるだけ。その電文が、あとから出た訂正・取消で無効になっていないか、いまも有効か（`docs/research/jma_data.md` の 2.1・3 章）は見ない。
- **この試作で扱っていない電文の形。** 津波、特別警報・危険警報を含む警報、震度 5 弱以上で「震度5弱以上未入電」が入る電文、深さ「ごく浅い」、マグニチュードの値がない電文などは、実物で確かめていない。照合器は「ごく浅い」「不明」の深さを文字のまま求める作りにしたが、試していない。
- **表記ゆれ。** 地域名を略したり（「千葉北東部」）、言い換えたりすると見つけられない。この場合は「地域ごと」の確認で止まる（止めすぎる側）ので、見逃しにはならない。

### 止めすぎる（正しい言い換えを止める）例

見逃しではありませんが、作る側が気をつける点です。

- 「発表した」「発表時刻」の「発表」を、警報の状態の「発表」と区別しない。そのため、警報が出ていない地域（「発表警報・注意報はなし」の地域）の名前と同じ文に「〜が発表した」と書くと、組み合わせの確認で止まる（「水戸地方気象台が…に発表した、北部の情報です。」で確かめた）。正しい例では、発表した官署と時刻を別の文に書いた。
- 正しい打ち消しも止める。「北部には強風注意報は発表されていません。」は、否定と組み合わせの確認で止まる（確かめた）。
- 「方が」は「地方が」に当たるので一覧から外した。このように、一覧の言葉が地名などの一部に当たると止めすぎる。
- 「安全」は、原文（たとえば避難の呼びかけ）にあっても止める。そういう電文は、この照合器では言い換えを出せない。

## 6. 分かったこと

- 言い換えを機械的に照合するには、言い換えの側に**書き方の約束**が要る。時刻は「M月D日H時MM分」、数は算用数字、地域と震度は同じ文、付加文はそのまま、など。約束から外れた書き方は「照合できない」として止める。これを言い換えを作る側の指示にも入れた。
- 文字の一致を見るだけでも、数値・時刻・地域・種類・取消と訂正の誤りは、かなり止められる（誤りの例 32 件をすべて止めた）。一方で、意味の誤り（反対のことを付け足す、役割の入れ替え、一覧にない言い回しの助言）は止められない（見逃す例 9 件）。
- 照合を通ったことは「食い違いが見つからなかった」というだけで、「正しい」ではない。画面にもそう書き、原文を常に並べて出すことにした。
- 最初に作った照合器には見逃しがあった（震源の地名の取り違え。震源の地名が震度の文にも出てくるので、「どこかにあるか」だけでは通ってしまった）。わざと誤りを入れた例を作ってから照合器にかけたので、初回の実行で気づけた。また、思いついた見逃しを実際に照合器にかけたところ、「解除されていません」のような状態の打ち消しが通ることが分かり、否定の確認を足した。
- 警報の電文の見出しには、もともと「注意してください」という呼びかけが入っている。照合器は原文での回数までは許すので、見出しの呼びかけを言い換えに残すことはできる。

## 7. 本番にするなら直すべき点

- **意味の照合**：反対のことの付け足しや役割の入れ替えを止めるには、文字の一致では足りない。たとえば、言い換えから事実を取り出し直して原文と比べる（逆向きの抽出）、別の仕組みで二重に確かめる、などを考える。どれを選んでも「照合を通った＝正しい」とは言えないので、原文を並べて出す作りは残す。
- **言い換えの書き方を型にする**：自由な文章ではなく、「いつ・どこで・何が」の型に値を入れる作りにすれば、照合しやすくなり、見逃しも減る。ただし「平易さ」とのかね合いを決める必要がある。
- **言葉の一覧の見直し**：予報・助言・安心の言葉の一覧は、思いついたものを入れただけ。実際の言い換え（API の出力）を多く集めて、一覧から漏れる言い回しを調べる必要がある。
- **扱う電文を広げる**：津波、特別警報・危険警報、指定河川洪水予報、震度 5 弱以上、訂正・取消の実物。
- **電文どうしの関係**：取消・訂正で無効になった電文の言い換えを出さない。いまは 1 件ずつ見ている。
- **XML の解析**：標準ライブラリの解析を使っている。DTD を含む XML は読まないようにしたが、本番では悪意のある XML への対策が確かなものにする。
- **画面**：スマートフォンの幅では、上の注意書き 3 つで最初の画面が埋まる（試作 C-A と同じ問題）。文言（公的情報の優先）は「！！仮の値！！」のまま。読み上げ（スクリーンリーダー）での確認はしていない。
- **出典と加工の表示**：画面の下に「出典：気象庁ホームページ」と、加工したこと・編集の責任が本プロジェクトにあることを書いた。書き方は `docs/research/jma_data.md` の 4.3 に合わせたつもりだが、決め直す必要がある。
