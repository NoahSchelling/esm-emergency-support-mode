## 2. 実機で確かめるべき点

### 共通

- [ ] HTTPS で配信して開けるか（方法は未定：！！仮の値！！）。HTTP の LAN のアドレスで開いたとき、位置・揺れ・向きなどが「使えない（HTTPS ではない）」になるか。
- [ ] 幅の狭い端末（375 ピクセル前後）で、横スクロールが出ないか。文字を大きくする設定にしたときも崩れないか。
- [ ] 端末を暗い表示にしたとき、すべての欄が読めるか。屋外の明るさで、橙・赤・灰の印が見分けられるか。
- [ ] 印の色だけでなく文字で状態が分かるか（色の見え方が違う人でも区別できるか）。
- [ ] 画面を裏に回して戻したとき、揺れと向きが「古い」になり、戻ると「取れた」に戻るか。
- [ ] 区域の欄で、位置が古くなったとき（120 秒、！！仮の値！！）に「この位置は古くなっています」と出るか。

### iPhone の Safari

- [ ] 「揺れと向きの許可を求める」を押したときに、許可を求める画面が出るか。押す前は揺れが「まだ値がない・分からない」のままで、「取れた」にならないか。
- [ ] 許可しなかったとき、揺れと向きが「許可なし」になるか。
- [ ] 「位置を取って区域を引く」で位置の許可を求める画面が出るか。断ったとき「許可なし」になるか。
- [ ] 通信の種類と電池が「非対応」になるか。

### Android の Chrome

- [ ] 許可を求める画面なしで、揺れと向きが「取れた」になるか。
- [ ] 揺れの値の出方（重力を除く値が空の端末で、表示がどうなるか）。

### 表示の誤解

- [ ] 「いまのモード」の「平常」を、見た人が「安全」と受け取らないか（添え書きは「安全という意味ではありません」）。
- [ ] 段階の名前「安全確保後」を、「安全になった」と受け取らないか。
- [ ] 「この端末が記録した揺れ（震度ではありません）」の値を、震度や地震の大きさと受け取らないか。
- [ ] 「取れた」を「問題がない」と受け取らないか。
- [ ] 「あなたの申告（未確認）」の読み取り結果を、公的な情報と取り違えないか。
- [ ] 模擬データの印と帯が、切り取った画面の写真でも分かるか。

### 位置を扱うときの注意

- [ ] 実機で確かめるとき、実際の位置を記録・コミットしない。画面の写真に位置が写らないこと（緯度・経度は出さないが、市町村名は出る）。市町村名の写った写真もリポジトリに入れない。

## 3. 決めていないこと（！！仮の値！！）

- 公的情報の優先の文言。
- 申告のボタン（「緊急にしない」など）を、本番の画面でどこに・どう出すか。
