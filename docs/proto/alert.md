## 2. 外枠のレベルの決め方（`modules/alert/alert.js`）

1. 公的な発表の**種類の名前**を、決まった表でレベルにする（！！仮の値！！）。

   | 名前に含まれる語 | レベル | 色 |
   | --- | --- | --- |
   | 注意報、津波注意報 | 2 | 黄 |
   | 警報、津波警報 | 3 | 赤 |
   | 危険警報、土砂災害警戒情報 | 4 | 紫 |
   | 特別警報、大津波警報、津波警報（大津波） | 5 | 紫（3 秒周期のフェード） |
   | 緊急地震速報、解除、なし、津波予報 | 使わない | — |

2. 現在位置の区域（`modules/area/` の警報の区域・市町村・府県のコード）と、最寄りの津波予報区（下）に当てはまる発表だけを使う。区域が 1 つに決まらないときは、候補すべてを使う（高いほうに倒す）。
3. **切迫**：最寄りの津波予報区に津波警報・大津波警報が出ていて、次のどちらかのとき。1 秒周期・フェードなしで点滅し、色はそのときのレベルの色（赤または紫）。
   - **国の津波浸水想定の区域の中**のとき（優先。2026-11-07 に変更、l4b の指摘への対応）。区域の外と分かったときは、距離にかかわらず切迫にしない（発表のレベルの色と点滅はそのまま）。
   - 区域が分からない（データがない・位置を外に送る取得に同意していない）ときだけ、海岸線から **1000m 以内**（！！仮の値！！、このアプリの目安）。このときは「海岸線からの距離は、このアプリの目安です。公的な基準ではありません」と出す。
   - 遅い点滅・点滅なしのときに、安心させる文（「区域の外です」など）は出さない。
4. 公的な発表を受け取れないとき、区域が分からないときは「分からない」。外枠は背景色のままにして、状態の行に「警報が出ていないという意味ではありません」と出す（BW-S3）。

**BW-S1 との関係**：レベルは発表の名前から決めるだけで、危険を推定しない。切迫の判断には、国（都道府県）が公表した津波浸水想定を優先して使う。海岸線からの距離のしきい値だけは独自の目安で、浸水想定が分からないときに限って使い、画面に「公的な基準ではありません」と出す。

**浸水想定の取得と位置**：ハザードマップポータルサイトの津波浸水想定のタイル（`https://disaportaldata.gsi.go.jp/raster/04_tsunami_newlegend_data/{z}/{x}/{y}.png`、ズーム 16）を取りに行き、その地点の画素の色の有無を読む（色あり＝区域の中、透明＝区域の外、タイルなし（404）・失敗＝分からない）。どのタイルを取ったかで位置が外に伝わるので、メニューの「事前情報収集」で同意した後だけ取りに行く（標高 API と合わせて、まとめて 1 回の同意）。デモの 4 地点は 2026-11-07 に調べた結果をデータに入れていて、デモでは取りに行かない。

| デモの地点 | 標高 | 浸水想定 | 海岸線からの距離 |
| --- | --- | --- | --- |
| 焼津市内の架空の地点 | 1.4m | 区域の中 | 約 560m |
| 相馬市内の架空の地点（2026-11-07 に移した。前の地点は潟の水面に近かった） | 5.9m | 区域の中 | 約 1040m |
| 千葉市役所（およその位置） | 3.1m | 区域の中 | 約 520m |
| 練馬区役所（およその位置） | 40.7m | タイルなし（分からない） | 範囲の外 |

## 3. 海岸線のデータ（`modules/alert/data/coast.json`）

- 気象庁「予報区等GISデータ」の「津波予報区」（海岸線に沿った線と、津波予報区のコード）から、静岡県（380）・福島県（250）・千葉県九十九里・外房（310）・千葉県内房（311）・東京湾内湾（312）を取り出した。
- 線を 20m の許容誤差で簡略化した（頂点 486,260 → 21,439、最大の誤差 約 21m）。約 190KB、gzip で約 70KB。
- 作り方は `modules/alert/data/SOURCE.md`。同じ入力から同じ JSON ができることを確かめた。

## 4. 試作 C-A の変更

電文の Body の Item から、区域（Area の Code・Name）ごとの種類（Kind の Name・Status）を取り出すようにした（`items`）。値は書き写すだけで、判断はしない。

2026-11-07：津波警報・注意報の電文の予報区ごとの予想される津波の高さ（`Item/MaxHeight` の `jmx_eb:TsunamiHeight`）も取り出すようにした（`max_height`：`description`・`value_m`・`unit`・`condition`・`unbounded`）。「10m超」「巨大」のように上限がない・数値でない値は `unbounded: true` にする。手元に本物の津波の電文がないので、気象庁の XML の形に合わせた試験用の電文でテストした（本物の R06 形式の電文での確かめは次の段階）。手元の本物の電文（広島県の気象警報・注意報）でテストした。

現在位置モードの制限：

- C-A は最近の電文（10 件）しか持たない。それより古い発表は見えない。
- 同じ題名の電文は新しい 1 通だけを使う。
- 区域のデータは静岡県だけなので、静岡県の外では「この地域への発表を選べません」になる。

## 6. 実機で確かめるべき点

- 外枠の点滅が、屋外の明るさで見えるか。速い点滅が気分を悪くさせないか（1 秒に 1 回で、WCAG の「1 秒に 3 回まで」の範囲）。「動きを減らす」の設定でも点滅は止めていない。
- 黄色の外枠が、ライトの背景（白）で見えるか。内側に 2px の線を足してある。
- デモを、見る人が本物の警報と取り違えないか（帯・状態の行・避難者の表示に「過去の記録の再生」「模擬」を出している）。
- 現在位置モードで、本物の C-A（気象庁の電文）を受けたときに、区域のコードが合うか。R06 形式の電文（市町村等の Item）での確認はしていない。
