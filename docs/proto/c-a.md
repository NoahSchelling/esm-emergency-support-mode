# 試作 C-A：公的発表の受信状況を見せる画面

- 作成日：2026-11-04（日本時間）
- 置き場所：`proto/c-a/`
- 状態：**試作**。本番では使わない。

## 1. 何をするものか

気象庁の防災情報 XML の Atom フィードを定期的に取得し、**「情報の状態」**を画面に出します。内容の判断はしません。

| 画面の部分 | 中身 | 安全の下限 |
| --- | --- | --- |
| 上部の帯 | 模擬データのとき、人工的な途絶（デモ）のとき、更新が途絶えている可能性があるときに、それぞれ常に表示する | BW-S3 |
| 公的な発表を優先してください | 公的情報を優先する旨の表示。**文言は「！！仮の値！！」** | BW-S2 |
| 受信の状態 | 最終受信からの経過時間、最終受信の時刻、最終取得の時刻、直近の取得エラー | BW-S3 |
| 警報の新着 | 新しい警報がないときは「新しい警報は受信していません。安全という意味ではありません。」と表示する | BW-S3 |
| 最新の発表 | 種類、対象地域、発表時刻、発表官署、情報の種類、見出し（受信したまま）、元の電文へのリンク | BW-S1 |
| 最近の受信 | 新しい順に最大 10 件 | BW-S1 |
| フィードごとの状態 | フィードごとの最終取得・最終受信・エラー | — |
| デモ操作 | 更新の途絶を人工的に起こすボタン（`--demo` で起動したときだけ出る） | — |

### 言葉の意味

- **最終受信**：フィードの内容が新しくなった（フィードの更新時刻が進んだ、または新しい電文が載った）のを確かめた時刻。
- **最終取得**：フィードの取得（通信）に成功した時刻。内容が変わっていなくても進む。
- **更新が途絶えている可能性**：最終受信から `--stale-after` 秒（既定 600 秒）以上たったときに出す。通信は成功しているのに内容が古いまま、という途絶も拾うため、「最終取得」ではなく「最終受信」で判定する。
- **警報の新着**：直近 `--warning-window` 秒（既定 3600 秒）に、**種類名に「警報」を含む**電文を受信したかどうか。種類名による機械的な絞り込みで、内容は判断していない。
- 画面自身がサーバーから状態を受け取れなくなったとき（10 秒以上）も、「この画面はサーバーから状態を受け取れていません」と出す。経過時間は画面の側でも数え続けるので、サーバーが止まっても途絶の表示に切り替わる。

### 安全の下限への対応

- **BW-S1**：受信した文字列はそのまま表示する。並べ替えと項目の抜き出しだけを行う。「警報」の判定も種類名の文字列で行い、内容から危険度などを推し量ることはしない。
- **BW-S2**：画面の上の方に、公的な発表を優先する旨を常に出す（文言は仮）。README にも書いた。
- **BW-S3**：「安全」「異常なし」といった言葉や、安心を連想させる緑色を使わない。警報の新着がないときは決まった文言を出し、途絶の可能性があるときは「受け取れていないだけかもしれない」と添える。まだ何も受信していないときは「警報の有無は分かりません」と出す。
- **BW-S4**：該当する処理はない。

## 2. 動かし方

Python 3（3.11 以降を想定。3.13 で確認）だけで動きます。追加のインストールは要りません。

### 通常の起動

```bash
python3 proto/c-a/server.py
```

ブラウザで `http://127.0.0.1:8000/` を開きます。

- 既定（`--source auto`）では、最初の 1 回だけ気象庁のフィードを取りに行き、**取得できなければ模擬データに切り替えます**。切り替えた理由は画面の下に出ます。
- いったん実データを受信したあとは、**取得に失敗しても模擬データには切り替えません**。そうすると本物の途絶が隠れてしまうためです。失敗は「直近の取得エラー」と途絶の表示で知らせます。

### デモ用の起動（途絶をすぐ見せたいとき）

```bash
python3 proto/c-a/server.py --demo --poll 5 --stale-after 30 --warning-window 600
```

5 秒ごとに取得し、30 秒受信がないと途絶の表示に切り替わります。画面の一番下に「デモ操作」が出ます。

| ボタン | 起きること |
| --- | --- |
| 途絶を起こす（取得失敗） | サーバーが取得を失敗したことにする。「直近の取得エラー」に「（デモ）」と出て、最終取得も最終受信も止まる |
| 途絶を起こす（内容が更新されない） | 取得は成功したことにするが、内容は変わらないことにする。エラーは出ないのに最終受信だけが止まる。気付きにくい途絶の例 |
| 途絶を止める | 元に戻す。すぐに 1 回取得し直す |
| 模擬の警報電文を 1 件入れる | 模擬データのときだけ出る。「警報の新着」の表示が切り替わるのを見せる |
| 画面側の受信を止める／再開する | ブラウザがサーバーに問い合わせるのを止める。サーバーと画面のあいだの途絶の例 |

人工的に途絶させているあいだは、画面上部に「デモ：人工的に更新を途絶させています」と出ます。画面側の受信を止めたときも、メッセージに「（デモ）」と添えます。

### 模擬データだけで動かす

```bash
python3 proto/c-a/server.py --source mock --demo
```

### 主なオプション

| オプション | 既定値 | 意味 |
| --- | --- | --- |
| `--source` | `auto` | `auto`／`live`（実データのみ）／`mock`（模擬データのみ） |
| `--poll` | 60 | 取得の間隔（秒） |
| `--stale-after` | 600 | この秒数だけ新しい受信がないと「途絶えている可能性」を出す |
| `--warning-window` | 3600 | 警報の新着を数える期間（秒） |
| `--demo` | なし | デモ操作を有効にする |
| `--host` / `--port` | `127.0.0.1` / 8000 | 待ち受けるアドレス。既定では自分のパソコンからしか見えない |
| `--mock-every` | 3 | 模擬データで、何回の取得ごとに新しい電文を 1 件増やすか |
| `--timeout` | 15 | 通信のタイムアウト（秒） |

### テスト

```bash
python3 -m unittest proto/c-a/test_server.py
```

## 3. 模擬データについて

- 模擬データはプログラムの中で作る架空のデータです。種類名は「模擬電文：…」、地域は「模擬地域A」など、官署は「模擬官署」で、本文にも「これは模擬データです。気象庁の発表ではありません。」と入れています。画面を切り取っても本物と見分けられるようにするためです。
- 模擬データのあいだは、画面上部の紫の帯、ページの題名の「【模擬データ】」、各電文の「模擬」の印を常に出します。
- 模擬データの電文の形（Control・Head などの部分の分け方）は、**実物で確かめていない想定**に合わせて作っています（`docs/research/jma_data.md` の 3 を参照）。模擬データで動いたことは、実データで動くことの証明になりません。

## 4. 確かめていないこと

- 2026-11-04 の時点で、この実行環境からは気象庁のサイトに接続できません（プロキシが拒否）。そのため**実データでは一度も動かしていません**。
- フィードの URL（`extra.xml`・`eqvol.xml`）、電文の中の要素の名前（発表時刻・情報の種類・対象地域・運用種別）は、どれも未確認の想定です。読み取れない項目は、推測せずに「読み取れませんでした」と表示する作りにしています。
- 「訓練」「試験」の電文は、電文の中の運用種別が「通常」以外なら印を付けて表示するだけで、まだ除外していません。
