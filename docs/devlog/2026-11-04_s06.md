# 2026-11-04 s06

## 目的

`docs/review/check-secrets_review.md`（s05 の攻撃者視点レビュー）の指摘と、s01 の「次にやること」をもとに、秘密情報・個人情報の検査を補強する。

1. Git の pre-push フックで `scripts/check-secrets.sh --push` を呼ぶ。
2. コミットメッセージと作成者情報を検査する。
3. レビューの深刻度「高」と「中」を修正する。「低」は対応するかを判断し、理由を書く。
4. 検査スクリプトの自動テストを `tests/` に作る。偽の値はテストの実行時に断片をつないで作る。
5. 公開前の最終確認のために、全履歴を検査するモードを足す。

## 決めたこと（理由・却下した案）

- **作業 1 の pre-push フックは、すでにあった。** s02_pre-push の回（PR #5）が `.githooks/pre-push` を作り、`--push <コミット>...` を呼んでいた。この回は作り直さず、レビューの CS-10（ほかのリモートの追跡参照を「プッシュ済み」とみなす）と CS-01（ブランチ名・タグ）を直す形で強くした。
  - 送り先が名前のあるリモートなら、そのリモートの追跡参照と、Git が渡す送り先の今のコミットだけを「プッシュ済み」とみなす（`--remote`、`--base`）。URL を直接指定したときは、送り先の今のコミットだけを使う（`--no-remotes`）。
  - 送る側と送り先の参照名を `--ref` で渡し、名前も検査する。注釈付きタグは、タグのメッセージとタガーも検査する。
- **作業 2：コミットメッセージと作成者は、2 か所で検査する。**
  - 新しい Git の commit-msg フック（`.githooks/commit-msg` → `--message`）：コミットを作る前に、メッセージと、作成者・コミッターの名前とメールアドレスを止める。`git commit -v` で付く「はさみの行」より下は、Git がメッセージから消す差分なので見ない（消そうとしている値で止まるのを防ぐ）。
  - `--push`・`--range`・`--all`：各コミットの作成者・コミッター・メッセージも検査する。プラミング（`commit-tree`）や GitHub の画面で作られたコミットは commit-msg を通らないので、ここで拾う。
  - メールアドレスの許可：GitHub の noreply のドメイン、example のドメイン、それに完全に一致する 3 つのアドレス（GitHub のマージコミットのコミッター、Claude の共同作成者の行、SSH のクローン URL の形）。今の履歴の作成者とコミッターがすべて許可に入ることを、ドメインと「noreply かどうか」だけを数えて確かめた。
- **検査スクリプトは、ほぼ書き直した。** 理由：ファイル名を伏せる（CS-13）には、すべての一致が出そろってから表示する必要があり、1 行ずつその場で表示する作りのままでは直せなかったため。
  - 検査した文字列（ファイル名、追加行、メッセージの行など）を「単位」として記録し、一致はまとめて最後に表示する。ファイル名に一致があれば、そのファイルのすべての行の表示で、名前を番号に置き換える。
  - 見つけた値は「長さ」だけを出す（以前は先頭 2 文字も出していた。メールアドレスでは本名の頭文字になりうるため）。
- **bash と git だけで動く、という s01 の方針は保ち、python3 は「あれば足す」にした。** NFKC の正規化、Shift_JIS・EUC-JP の判定、base64・16 進の復号は、bash だけでは書けないか遅い。python3 は `-I`（分離モード）で 1 回だけ起動し、全行をまとめて渡す。python3 がないときは「未実施」と表示し、従来の比べ方は続ける。
  - python3 が途中で失敗した、または検査した件数が送った件数と合わないときは止める（何もしないで 0 で終わる偽物を置かれても、黙って通さないため）。
  - 却下：全体を python で書き直す案（python3 がない環境ではコミットができなくなる。s01 の方針からも外れる）。
- **バイナリの判定は、Git と同じ規則（先頭 8000 バイトに NUL があるか）を、自分で中身に当てて行う。** `.gitattributes` の指定では答えが変わらない。そのうえで差分は `--text --no-textconv` で取り、属性に関係なく中身も検査する。バイナリのファイルは、画像（警告）を除いて止める。UTF-16 のテキストもここで止まる。
  - 却下：UTF-16 を変換してから検査する案。止めて「UTF-8 で保存し直す」よう伝えるほうが単純で、取りこぼしがない。
- **種類の変更（CS-03）は、差分の対象を「削除以外すべて」にして塞いだ。** 「含めるもの」を並べる形から「除くもの」を書く形に変えたので、Git に新しい種類が増えても漏れない。
- **検査の仕組み自体への変更（CS-05）**：フックの実行権限を外す変更、フック・検査スクリプト・Claude Code の設定・ワークフローを消す変更や名前を変える変更は止める。それ以外の中身の変更は警告にした（この回のように、正当な変更も多いため）。`.gitattributes` に差分を隠す属性を足す変更は止める。
- **CI は、検査スクリプトを 2 回走らせる。** ベースのブランチ（push のときは main の前の版）から取り出した「信頼できる版」と、変更に含まれる版。前者で、変更が自分の検査を止める手を塞ぎ、後者で、新しい規則をすぐ効かせる。対象も、すべてのブランチとタグへの push に広げた（CS-11）。テストの job も足した。
- **禁止語リストは、PR の CI では使わない（CS-14）。** 個人語の検査は、main への push のときだけ、Environment `personal-words` の Secrets で行う job に分けた。Environment を main のブランチだけに限れば、PR の中でワークフローを書き換えても読み出せない。登録がないときは失敗にした（CS-16 の修正案のとおり。公開までに必ず気づくため）。
  - 却下：禁止語をハッシュにして Secrets に置く案。辞書で総当たりすれば名前は割り出せ、仕組みも重くなる。読み出せる経路を断つほうが確実。
- **Claude Code のフック（CS-04・CS-18）**：
  - Git のフックを外すコマンド（フックを飛ばす指定、`git commit -n`、`core.hooksPath` に触れるもの）は、いつでも止める。`core.hooksPath` は読み取りも止める（書き方の見分けを機械でやると抜けが出るため）。`.githooks` に設定し直すコマンドだけは許す。
  - `commit` や `push` の語がコマンドのどこかにあれば検査する（絶対パスの git、エイリアス、スクリプト経由を拾うため。広く当たってもよい）。そのとき、Git のフックが有効で、3 つのフックに実行権限があるかも確かめる。
  - `.claude/settings.json` の `permissions.deny` に、フックを飛ばすコマンドの形と、GitHub の MCP の書き込み系の 2 つの道具を足した（手元のフックを通らないため。CS-11）。
- **処理時間（CS-15）**：メールアドレスは、`@` の前後の決まった幅だけを見る。長い行は、重なりを持たせた 4096 バイトずつに分けて見る。規則ごとに安い前置きの照合を付け、どれにも当たらない行は規則の照合を飛ばす。
- **全履歴のモード `--all`（作業 5）**：すべての参照から辿れるコミットの差分・メッセージ・作成者、すべての参照名、すべての注釈付きタグを検査する。公開前は `--all --require-denylist` で使う。`--require-denylist` は、どのモードでも「個人語の検査ができないなら止める」。
- **テスト（作業 4）**：`tests/check-secrets.test.sh`。使い捨てのリポジトリと、使い捨てのベアリポジトリをリモートとして作り、実際にコミットとプッシュをする。漏れを含むコミットは、フックを外さずにプラミングで作る（s02_pre-push の学びのとおり）。Git の全体設定は読まない。偽の値は実行時に断片をつないで作る。CI でも走らせる。

## 試して分かったこと（失敗を含む）

- 自動テストは 17 の群、161 件。すべて合格した（約 30 秒）。python3 がない状態は、PATH から python3 を外して試した。
- 全履歴の検査（`--all`、32 コミット、追加行 2.85 万）は、停止 0・警告 0 だった。時間は約 7 秒（規則を増やす前は約 3.7 秒）。
  - 最初の版は約 25 秒かかった。原因は 2 つあった。規則の前置きの照合の型を、クォートせずに展開したため、型がファイル名の展開にもかけられていた（行ごとにディレクトリを読んでいた）。スクリプト全体でファイル名の展開を止めて直した。また、型の 1 つに空白が入っていて 2 つに割れ、空の選択肢ができて「どの行にも当たる」状態になっていた。空白を除いて直した。
- テストで、**新しく作った不具合**が見つかった：`--push` に存在しない 40 桁のハッシュを渡すと、止まらずに 0 で終わった（`git rev-parse --verify` は、40 桁のハッシュなら存在を確かめずにそのまま返すため）。「オブジェクトとして存在するか」を確かめる書き方に直した。以前の版はこの書き方ではなかったので、書き直しで入れた誤りだった。
- 自分の検査スクリプトで、この回の変更をステージして検査した。テストのファイルの「URL の中のパスワード」の例（変数の展開の形）が、新しい規則に当たって止まった。変数の展開（`$` で始まる値）を例の値として許すように直した。

- この環境では、Git の設定が環境変数で足されている（クラウドの環境の設定）。そのため、この環境の検査は毎回「環境変数で Git の設定が足されています」の注意を出す。害はないが、目に付く。

- `git rev-parse` の件と同じく、bash の `$!`（最後に起動した裏の処理）が、ループの中の別の裏の処理で上書きされて、差分を取る git の失敗を見落とす作りになりかけていた。書く段階で気づき、読み口を番号で持つ形にした。

- **このセッションの個人語の検査は「未実施」だった**（環境変数 ESM_DENYLIST_FILE が未設定）。テストの中だけで、架空の語を入れた禁止語ファイルを使った。この回に足した文書に個人の情報がないことは、人の目で確かめた。

## Claude の使い方（どの機能を何のために）

- **Read**：レビュー文書、s01・s02_pre-push・s05 の開発ログ、検査スクリプト、フック、設定、ワークフローを読んだ。
- **Write・Edit**：検査スクリプト、3 つのフック、Claude Code のフックと設定、ワークフロー、テスト、CLAUDE.md、README、開発ログを書いた。
- **Bash**：テストの実行、全履歴の検査の時間の計測、規則ごとの処理時間の計測（作業用の場所に置いた計測用のスクリプト）、main の版のスクリプトでの検査。
- **Hooks（PreToolUse）**：この回に直したフックが、そのままこの回のコマンドにも効いた。フックを飛ばす文字列を含むコマンドを実際に止めたことで、動きを確かめられた。
- サブエージェントは使っていない。

## l4b へ戻す学び

- 「検査を書き直す」ときは、先にテストを用意すると、書き直しで入れた抜け（今回は、存在しないハッシュを通してしまう誤り）をすぐ拾える。止まる側に倒すはずの検査は、黙って 0 で終わる経路がないかを、テストで直接確かめる。
- bash で型の照合を変数に入れるときは、ファイル名の展開を止める。止めないと、遅いだけでなく、作業ディレクトリの中身で結果が変わりうる。
- 守りを止める操作は、運用の約束だけでなく、その操作自体を検査の対象にする。今回、自分の作ったフックが自分のコマンドを止めたことで、約束が仕組みになったことを確かめられた。
- 秘密を守るための秘密（禁止語リスト）は、「読める経路」を断つ設計にする。PR が書き換えられるワークフローに渡さない。

## 次にやること

- Secret scanning と push protection を有効にする（公開リポジトリでは無料）。分けて書いたキーなど、この検査で拾えないものの別の層になる。
