# 2026-11-07 s01

## 目的

避難者の画面に、公的に指定された避難場所への方向を矢印で示す。そのために、(1) 国土地理院の指定緊急避難場所データ（静岡県）を端末で使える形にし、(2) 位置・方位から避難場所の方向を計算するモジュールを `modules/evac/` に作り、(3) `app/` に避難者向けの表示を加える。通信が細い発災後を想定し、地図は使わず、矢印・距離・名前だけを出す。

## 決めたこと（理由・却下した案）

- **加工したデータをリポジトリに置いた**（`modules/evac/data/shizuoka_evac.json`、2,885 か所、約 270KB、gzip で約 65KB）。国土地理院コンテンツ利用規約（公共データ利用規約 第 1.0 版）は、出典と加工の表記で複製・加工・公衆送信を認めている。指定緊急避難場所データの「ご利用上の注意」は第三者への提供を禁じず、注意の 1〜3 を正確に伝えることを求めている。そこで注意の原文を README・データ・画面に入れた。却下：データを置かずスクリプトだけをコミットする案（試験と画面が動かず、条件を満たせば置けると読めたため）。公開前に人が確かめる点は `docs/research/evac_sites.md` の 9 章。
- **データの形は 1 行 1 か所の配列**（共通 ID、名前、市町のコード、緯度、経度、災害の種別 8 文字の「1/0」、備考）。住所は画面に出さないので入れなかった。座標は小数 6 桁。共通 ID の順に並べた。市町の名前は、共通 ID の 2〜6 文字目のコードで国土地理院の市町ごとの一覧から引いた（都道府県別の CSV には市町の列がないため）。
- **災害の種別はモジュールが選ばない。** 呼び出す側が渡さないときは `error`。画面では、模擬のシナリオ（津波）があるときだけ避難場所を選ぶ。ないときは「公的な発表を受けていないため、避難場所を選んでいません」と出す。却下：画面に種別を選ぶボタンを置く案（依頼の「入力欄は置かない」に反し、種別の判断を利用者に負わせるため）。
- **矢印を出す条件を 11 個に絞り、1 つでも欠けたら文と北を上にした図だけにした**（`modules/evac/README.md`）。値はすべて ！！仮の値！！。サブエージェントの指摘で、次の 4 つを足した・変えた。
  - 精度の分からない方位（Android）は、GPS の進行方向と 20 度以内で一致してから 20 秒だけ使う。歩いているあいだは一致し続けることを求める。方位が途切れたら一致の記録を消す。
  - 位置が 15 秒より古いときは矢印を出さない。
  - 横向き・上下逆では矢印を出さない（符号を実機で確かめるまで）。
  - 傾きの上限を 60 度から 45 度に下げた。
- **傾いた画面に描く矢印の角度を、幾何的に求めることにした。** 最初は「方位の差」をそのまま角度にしていた。しかし、傾いた画面では、上から見た向きがずれる（縦向きで 20 度傾けると、前後方向が cos 20° だけ縮む）。そこで、描いた矢印を真上から地面に投影した向きが目標の方位になるように角度を求める（`screenArrowDeg`）。横向きで傾けると最大約 35 度ずれていた問題も、これで解消した。
- **Android の `deviceorientationabsolute` の北は磁北とみなして偏角を引いた。** Android の回転ベクトルの座標系による判断で、実機で確かめる点にした。iPhone の `webkitCompassHeading` も磁北基準。
- **偏角は国土地理院の 2020.0 年値の近似式を使った**（出典を README に書いた）。ページの計算例（東京、7°36.5′）をテストで再現した。出典が確かめられたので「仮の値」にはしていない。2020 年からの変化は未確認。
- **GPS の進行方向で方位を回す（足し引きする）補正はしなかった。** 端末を進行方向に向けているとは限らず、回すと誤った矢印を作りうるため。かわりに次の 2 つに使った。
  - 精度の分からない方位を「確かめる」（一致したら一時的に使う）。
  - 大きく食い違ったら矢印を消す。
  
  位置が変わるたびに方位と距離は計算し直す。依頼の「GPS データに変化があれば方位表示も補正」は、この形で受けたと解釈した。
- **Android の Chrome がふつうの `deviceorientation`（北を基準にしない）も出すので、`deviceorientationabsolute` があるブラウザではそちらを無視する。** 混ざると、最新の値が北を基準にしない値になりうるため。iPhone 風と Android 風の値が窓の中で混ざったときも使わない。
- **結果に、位置も、避難場所の座標も、位置から求めた偏角も入れない。** 避難場所の座標を入れると、距離と方位から位置を正確に計算できてしまうため。名前と距離・方位からおよその位置が分かることは README に書いた。
- **避難者の表示は `app/evac/` の独立したスクリプトにした。** 支援者の画面（`app/main.js`）が読み込めなくても動くようにするため。`main.js` には次の 2 つだけを足した。
  - Android の向きのセンサーを `deviceorientationabsolute` にする変更。
  - 避難者の表示への通知（模擬の発表とその解除、受信時刻）。
- **模擬の指示は、模擬の発表文の引用の形にした**（「【模擬】津波警報（模擬）の発表文：「…」」）。アプリが自分で書いた避難の指示に見えないようにするため（サブエージェントの指摘）。模擬の解除で方向の表示をやめる。
- **北を上にした図は、矢印ではなく円の上の点と破線にし、色も矢印と分けた。** 端末の向きと関係のない図を、矢印として追われないようにするため（サブエージェントの指摘）。
- **「通れない」の除外は、方向に加えて、そのとき示していた場所も記録する。** 移動して方位が変わると、方向だけの除外では同じ場所が戻ってくるため（サブエージェントの指摘）。
- **公的データが使えないときの案内先**：公的（地理院地図）を先に出す。民間（Yahoo!天気・災害の避難場所マップと避難情報のページ）は「民間のサイトです。公的な発表ではありません」と添えて後に出す。どれを出すかは ！！仮の値！！ で、人が決める。
- **「強い衝撃」の表示は場所だけ作り、既定では隠した。** 検知は次の回。
- **津波避難ビルは調べただけ**（静岡県で機械可読の一覧は見つからなかった。静岡市は、指定緊急避難場所の一覧で確認するよう案内している）。
- **開発ログの日付は 2026-11-07 にした。** 依頼では 2026-11-06 だったが、作業した日は日本時間で 11-07。人に確かめて決めた。

## l4b へ戻す学び

- 画面に描く矢印は「方位の差」ではない。傾いた画面に描いた線を、人は真上から地面に投影して読む。投影の関係を式にし、端末の姿勢を別の方法で作って検算する。
- 精度の値が得られないセンサーの値は、「安定している」ことでは正しさを保証できない。一定の偏りは揺れの検査では見えない。別の情報源（GPS の進行方向）で確かめたときだけ、短い時間使う。
- 位置を使う計算では、値の古さを必ず入力に入れる。センサーの側の「古い」の基準（120 秒）が、計算の側で許せる古さと同じとは限らない。
- テストの期待値を実装と同じ式で計算すると、何も確かめていない。手で計算した値か、別の方法（物理的な検算）で作る。
- `.gitignore` のひな形（Python の `lib/`）は、ほかの言語のディレクトリ名に当たる。新しいディレクトリを作ったら `git check-ignore` で確かめる。
