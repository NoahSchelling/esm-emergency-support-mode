# 2026-11-05 s06

## 目的

BW-S4 のための、助言（メンタルヘルス・医療）の入口（インターフェース）を作る。助言の中身は実装しない。

## 決めたこと（理由・却下した案）

- **置き場所は `modules/advice/`。`modules/fragment/` とは別にした。** 解析器が助言の処理に近づかないようにするため。解析器が advice を読み込まないことをテストで確かめる。
- **門（ゲートウェイ）と提供元の約束（コントラクト）の 2 つだけを作った。** 既定は提供元なしで、どの問い合わせにも `unsupported` を返す。BW-S4 の「実装しない」と「将来の追加に備えたインターフェースのみ」の両方を満たす形。
- **提供元の結果は門で検査し、外れたら `error` に置き換える。** 共通の形、`source` に `jma` `user` `device` を使わない（助言を公的発表や利用者の申告に見せかけない、BW-S1）、公的情報の優先と公的発表でないことの旗（BW-S1、BW-S2）、安全を言い切る言葉を禁じる（BW-S3）。
- **提供元に渡すのは `topic` だけ。** 利用者の文面や位置は渡さない（位置などの個人の情報を端末の外へ出さない約束のため）。
- **方針の説明文は、方針と「公的な発表と指示を優先」だけにした。** 最初は「必要なときは救急などの公的な窓口に連絡してください」と書いたが、行動の指示で、医療の助言に近いと気づいて外した。
- **却下：試験用の提供元をモジュールに同梱すること。** 同梱すると「提供元がある」状態が既定になりうる。試験用の模擬は、テストの中だけに置き、文面は「！！仮の値！！」にした。
- **却下：心理的な言葉の検出（「怖い」などを見つけて何かを返す）。** 検出して返す処理は、それ自体が BW-S4 の対象になりうる。入れていない。

## l4b へ戻す学び

- 「実装しない」ものの入口を作るときも、入口が出す説明文が助言にならないか、同じ基準で見直す。方針の説明は、言うことを最小にする。
- 入口は、既定で閉じておく（提供元なし）。開けるのは、呼び出し側の明示と設計の見直しのあと。
- 検査を通ることと、中身が適切なことは別。検査の限界は文書に書いておく。
