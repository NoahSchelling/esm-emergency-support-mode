# 2026-11-05 s04

## 目的

緯度・経度と誤差から、市町村と、気象庁の警報・注意報の区域のコードを端末の中で引くモジュールを `modules/area/` に作る。対象は静岡県。気象庁の予報区等 GIS データの取得方法と利用条件を調べ、`docs/research/jma_data.md` に追記する。

## 決めたこと（理由・却下した案）

- **警報の「市町村等」は 2026-02-26 版の GIS（体系整理に伴う発表区域変更後）を使った。** 体系整理は 2026 年 5 月 29 日に始まっていて（`other_data.md` 10 章）、いま有効なのはこの版。静岡県分はコード表（2026-10-19 版）の 37 件とコードも名前も一致した。
- **「市町村」は「市町村等（地震津波関係）」の区域を使った。** 警報の「市町村等」は、静岡市・浜松市が「北部」「南部」に分かれていて、市町村ではない。地震津波関係のデータは区ごとで、地震情報の電文の市町村等コードとも同じ。名前は気象庁の値のまま（「静岡清水町」なども書き換えない）。
- **上位の区域（市町村等をまとめた地域等・一次細分区域等・府県予報区等）は、GIS を重ねるのではなく、公式のコード表の対応から引いた。** 府県予報区等・一次細分区域等の GIS は 2019 年版のままで、体系整理のあとも正しいかが GIS ページに書かれていない。コード表は 2026-10-19 版で新しい。ただし GIS とも照合し、555 点ですべて一致した。
- **簡略化の許容誤差は 30m。** 頂点は約 48 万から約 1.3 万になり、JSON は約 270KB（gzip で約 110KB）。判定のときに、誤差の半径にデータの誤差（約 31m）を足して調べるので、境界の近くでは誤差 0 でも必ず両側を候補にする。誤判定を「決めつけ」ではなく「候補が増える」側に倒した。
- **誤差の円が複数の区域にまたがるときは `status: "ok"`、`area: null`、`candidates` にすべて。** 共通の形では `value` は `ok` のときだけ入るので、候補を返すには `ok` にするしかない。そのかわり、1 つに決まったときだけ `area` を入れ、`determined` を明示した。`candidates[0]` を使われないよう、README と `detail` に「1 つに決めず」と書いた。
- **中心が県の外で、境界が調べる半径より遠いときは `unknown`。** 中心が海上でも、円が陸にかかるときは `ok` で候補と `outside_possible: true` を返す。海岸の線は簡略化と GIS の精度の両方でずれるので、陸の上にいる人を「海上」と決めつけないため。
- **誤差（`accuracy`）は必須にした。** 誤差なしで区域を決めると、境界の近くで決めつけになるため。ないときは `error`。
- **結果に位置そのものを入れない。** 結果がログなどに残っても位置が漏れないように。テストで確かめている。
- **ブラウザの読み込みは `browser/load.js` に分けた。** `area.js` は入出力なし、`node.js` は `node:fs` で読む。
- 却下：コード表を使わずに上位の区域の GIS も JSON に入れる案。データが倍以上になり、2019 年版の区域を使うことになるため。
- 却下：区域の境界を共有する形（トポロジー）にして簡略化する案。隣どうしの隙間と重なりはなくなるが、標準ライブラリだけで書くには手間が大きい。いまは誤差の幅を足すことで、隙間と重なりの影響を「候補が増える」にとどめている。

## 試して分かったこと（失敗を含む）

- 予報区等 GIS データは、全国分の zip だけ（1 つ 89〜481MB）。dbf は UTF-8、zip の中のファイル名は Shift_JIS だった。
- GIS ページには「国土地理院長の承認を得て…使用した」と承認番号（「情使」）が書かれている。国土地理院の Q&A では、使用承認を得て作った成果をさらに使うときは申請不要、ただし承認を得た者の許諾が前提とされている。気象庁の利用規約で許諾されていると判断し、承認の記載を承認番号ごと書き写した。国土地理院のページは curl で TLS 接続できず、Web 取得の道具（要約）で読んだので、**公開前に人が確かめる**こととして調査メモに書いた。
- 簡略化の検査（ランダム 3,000 点、半分は境界の近く）：もとの形との食い違いは 73 点。15 点は省いた小さな輪（岩礁など）の上、残りはすべて簡略化した境界から 22.1m 以内で、想定の 30.79m に収まった。
- 省いた小さな輪は 1,644 個、合計約 0.45km²。初島（約 0.52km²）は残った。
- 公共施設（静岡県庁、浜松・沼津・富士宮・熱海・下田の市役所）で、期待した市町村・区域が返った。座標は公共施設のおよその位置。
- 同じ入力から同じ JSON ができることを確かめた（乱数の種を固定）。
- 1 回の判定は約 0.2ms（Node.js、誤差 50m）。
- Chromium（Playwright）で `browser/load.js` から読み込んで動くことを確かめた。通信は同じサイトのモジュールとデータの取得だけだった。
- 検査スクリプトが `browser/load.js` の fetch の `credentials` の指定を「パスワードなどの代入の可能性」として止めた。誤検出だが、指定は fetch の既定と同じなので消して直した。フックは外していない。
- **個人語の検査は未実施。** 環境変数 `ESM_DENYLIST_FILE` が未設定で、フックがそのことを表示した。

## Claude の使い方（どの機能を何のために）

- Bash（curl）：GIS ページ・データ定義書・GIS の zip・個別コード表の取得。ダウンロードはスクラッチパッドの専用ディレクトリに置き、Python は `-I` で動かした。
- WebFetch：curl で TLS 接続できない国土地理院の承認申請のページを読むため。
- Python（標準ライブラリ）：シェープファイル・dbf・xlsx の読み取り、簡略化、照合。
- Node.js の `node --test` と Playwright：判定の関数のテストと、ブラウザでの動作確認。
- Claude Code のフック：コミットとプッシュのたびに検査が走った（上の誤検出を含む）。
- タスクの一覧：作業の区切りを追うため。

## l4b へ戻す学び

- 「区域のコード」は、使う電文の種類ごとに別の表（警報用の市町村等、地震用の市町村等）がある。同じ「市町村」でもコードの切り方が違うので、どの電文と突き合わせるかを先に決める。
- 簡略化したデータで判定するときは、簡略化の誤差を数字で持ち、判定の側でその分を広げる。誤判定を「別の区域を返す」ではなく「候補が増える」「判定できない」に倒せる。
- 位置を返すモジュールでは、結果に位置を入れない。
