# 2026-11-04 s04

## 目的

Git の pre-push フックを追加し、ターミナルから直接 `git push` したときも、プッシュするコミットを検査する。

## 決めたこと（理由・却下した案）

- **`.githooks/pre-push` を追加し、Git から受け取ったコミットを検査する。** Git は「どのブランチのどのコミットをプッシュするか」を標準入力で pre-push フックに渡す。フックはそのコミットを `scripts/check-secrets.sh --push <コミット>...` に渡す。検査するのは、そこから辿れるコミットのうち、まだリモートにないものだけ。
  - 理由：HEAD を基準にすると、別のブランチを指定してプッシュしたとき（例：`git push origin 別ブランチ`）、そのブランチの中身を見落とす。
  - 却下：pre-push フックから `--push` を引数なしで呼ぶ案（HEAD 基準になり、上の見落としが起きるため）。
- **`check-secrets.sh --push` に、コミットを任意で渡せるようにした。** 引数がなければ従来どおり HEAD を基準にする。そのため Claude Code のフックの動きは変わらない。解決できないコミットを渡されたときは、終了コード 2 で止める（検査できないときは止める方針どおり）。
- **リモートのブランチを削除するだけのプッシュは、検査を省略する。** 送るコミットがないため。ただし黙って通さず、「検査を省略しました」と表示する。
- `--staged` に余計な引数を付けたときは、誤用として止めるようにした。

## 試して分かったこと（失敗を含む）

- 一時リポジトリと、一時的に作ったリモート（bare リポジトリ）で試した。偽のキーはシェルで断片をつないで、その場で作った。漏れを含むコミットは、フックを有効にする前に作った。`--no-verify` は使っていない。
  1. 問題のないコミットのプッシュ：通った。
  2. HEAD は問題のないブランチのまま、偽キーを含む別ブランチを名前で指定してプッシュ：pre-push フックが止めた。リモートにも届いていない。
  3. 問題のないブランチのプッシュ：通った。
  4. リモートのブランチの削除だけ：検査を省略して通った。省略したことは表示された。
  5. `--staged` に余計な引数：終了コード 2 で止まった。
  6. `--push` に存在しないコミット：終了コード 2 で止まった。
- このクラウド環境のプッシュでは、「push negotiation failed」という警告が出た。Git の環境設定によるもので、フックとは関係なく、プッシュは成功している。
- **このセッションの個人語の検査は「未実施」だった**（ESM_DENYLIST_FILE が未設定）。

## Claude の使い方（どの機能を何のために）

- **Claude Code（クラウドのセッション）：** フックを追加し、スクリプトを拡張し、テストして、コミットとプッシュまで行った。
- **Hooks（PreToolUse）：** s01 で作ったフックが、このセッションのコミットとプッシュも検査した。テスト用のコマンドに `git commit` や `git push` の文字があるだけでも、本番リポジトリの検査が走った（害はない）。
- **一時ディレクトリ：** 本番のリポジトリやリモートを汚さずに、プッシュを止める動きを試した。

## 誤り記録

- CLAUDE.md の表で、検査スクリプトの説明が「下の 2 つから呼ばれる」のままだった。フックを追加して 3 つになったので、数を書かない言い方に直した。

## l4b へ戻す学び

- プッシュの検査は「何がプッシュされるか」を基準にする。HEAD を基準にすると、別のブランチを明示してプッシュしたときに抜けが生じる。Git の pre-push フックが受け取る情報を使えば、この抜けをふさげる。
- 漏れを含むテスト用のコミットを作るときは、フックを外すのではなく、フックを有効にする前に作る。「フックは外さない」という約束を、テストのときも守れる。
