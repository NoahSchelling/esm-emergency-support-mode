# 2026-11-04 s04

## 目的

試作 C-B を作る。気象庁の防災情報 XML の発表文（地震情報と気象警報）を平易な日本語に言い換え、言い換えが原文から外れていないかを機械的に照合する。食い違えば言い換えを表示しない。画面では原文と言い換えを並べ、発表時刻を出す。Python 3 の標準ライブラリと、素の HTML・JavaScript だけで作る。動かし方と、照合器が見逃しうる誤りは `docs/proto/c-b.md` に書いた。

- 言い換えを作る部分は、API を呼ぶ関数の形だけにする。この試作では API キーを使わず、Claude Code が言い換えの例文を作って照合器にかける。
- わざと誤りを入れた言い換えも作り、照合器が止めることを確かめる。

## 決めたこと（理由・却下した案）

- **ブランチ**：依頼では `proto/c-b` だが、実行環境が自動で決めたブランチ（`claude/` で始まる名前）を使った。依頼に「自動で決まる場合はそれで構わない」とあったため。手元のブランチは古い main の位置にあり、独自のコミットはなかったので、最新の main に合わせてから作業した（下の「試して分かったこと」）。
- **開発ログのファイル名**：依頼どおり `2026-11-04_s04.md` にした。セッションの最初は、手元のブランチに同じ名前のファイル（pre-push フックの回の記録）があった。リモートの main を確かめると、その記録は `2026-11-04_s02_pre-push.md` に改名されて s04 が空けてあったので、最新の main に合わせたうえで s04 を使った。作成の直前にも、手元とリモートの main の両方で空いていることを確かめた。
- **言い換えが扱う範囲（原文の範囲）を先に決めた**：地震は「情報の種類・情報の形態・発表時刻・見出し・発生時刻・震央地名・位置と深さ・規模・都道府県と細分区域の震度・固定付加文」、警報は「府県予報区と一次細分区域の種類・状態・付加事項」まで。画面の原文もこの範囲だけを出す。
  - 理由：照合は「原文の事実」と比べるので、比べる相手を先に決める必要がある。千葉の地震の電文は観測点まで入れると 35KB あり、全部を言い換えるのは現実的でない。
  - 警報の時系列の予想（風の強さ・危険度など）は入れなかった。予想の値を言い換えで扱うと、BW-S1 の「独自の予報を出さない」との境目が曖昧になるため。
- **照合器は文字の形で判断し、迷うときは止める**：意味は理解しない。時刻・数値・震度・警報の種類と状態・地域名・取消と訂正の言葉・予報や助言の言葉を拾い、原文と比べる。止めすぎる（正しい言い換えを止める）ことは許し、通しすぎることを避ける。止めたときも原文は必ず出る。
- **言い換えの側に書き方の約束を置いた**：時刻は「M月D日H時MM分」、数は算用数字、地域と震度・警報は同じ文、付加文はそのまま、警報の種類・地域・状態は電文の値のまま（`docs/research/jma_data.md` の 4.3）。約束から外れた書き方（漢数字、「14:50」）は「照合できない」として止める。この約束は、API 用の指示文（`build_prompt`）にも入れた。
  - 却下：言い換えの自由な言い回しに照合器を合わせる案。表記のゆれを全部拾うのは無理で、拾えない部分が見逃しになるため。
- **予報・助言・判断の言葉は「原文での回数まで」許す**：警報の見出しにはもともと「注意してください」が入っている。一律に禁止すると、見出しの呼びかけを言い換えに残せない。「安全」「安心」「心配いりません」や心理・医療の言葉だけは、原文になくても一律に止める（BW-S3、BW-S4）。
- **言い換えを作る部分は差し替えられる形にした**：`ExampleParaphraser`（例文を返す。既定）と `ApiParaphraser`（指示文を作り、外から渡された通信の関数に渡す形だけ。この試作では通信の関数を渡さないので、呼ぶとエラー）。API キーは読まない。認証情報は通信の関数の側で扱う前提。
- **食い違いのある言い換えは、文そのものを画面に送らない**：サーバーの段階で除く。わざと誤りを入れた例も、画面には「入れた誤りの説明」と「止めた理由」だけを出す。ただし、説明と理由の中には誤った語句が出ることがあるので、画面にそう書いた。
- **「見逃す例」も例文に入れた**：照合器が通してしまう誤りを、実際に通ることを確かめたうえで `known_misses` に置いた。確認用のスクリプトは、これが通らなくなったら失敗する。見逃しの記述（`docs/proto/c-b.md` 5 章）が実態とずれないようにするため。
- **保存した電文 7 件をリポジトリに入れた**：例文は特定の電文に合わせて作るので、電文がないと試作を再現できない。電文の URL がいつまで使えるかは分かっていない（調査メモ 1.3）。出典は `proto/c-b/bulletins/README.md` と README に書いた。
  - 熊本の地震の電文は `data/samples/` と同じ中身だが、試作のディレクトリだけで完結させるためにもう 1 つ置いた。
- **取消の電文は模擬で確かめた**：実物が手に入らなかった。テストの中だけで、保存した電文の情報の形態を「取消」に書き換えた模擬の電文を作った。ファイルには保存していない。
- **ポートは 8001**：試作 C-A（8000）と同時に動かせるようにした。

## 試して分かったこと（失敗を含む）

- セッションの最初に `git config core.hooksPath` を表示した。値は `.githooks` だった。
- 手元のブランチは古い main の位置にあり、リモートでは同じ名前のブランチが消えていた。リモートの main は 2 コミット進んでいて、そこで旧 s04 の開発ログが改名されていた。手元に独自のコミットがないことを確かめてから、最新の main に合わせた。
- 気象庁のフィードと電文は、curl でも Python（urllib）でも取得できた。高頻度の地震火山フィードには地震の電文が 1 件しかなかったので、長期フィードから同じ地震の 3 種類（震度速報、震源に関する情報、震源・震度に関する情報）を選んだ。警報は、発表・解除・付加事項ありの 3 種類が分かるものを選んだ。取得した電文は、まず作業用の場所に置いて、分離モードの Python で中身を確かめた。
- R06 形式の警報の電文は、地域ごとの状態（`Warning`）のほかに、時系列の予想（`Property`）や付加事項（`Addition`）を持っていた。見出しにも「強風に注意してください」などの呼びかけが入っていた。
- 照合器の作り直し：
  - 最初は、電文の中のすべての `Name` を地名として集めていた。これだと警報の種類名（「強風注意報」）まで「範囲外の地域名」と判定するので、地域の要素の `Name` だけに絞った。
  - 「方が」を一覧に入れたら「熊本地方が」に当たるので外した。「十分」は「十」＋「分」として漢数字の時刻に当たるので除いた。
  - 「最大震度3を千葉県北東部で観測」の「最大」付きの震度を、地域との組み合わせの確認から外していたので、含めるようにした。
- **誤りの例を初めて照合器にかけたとき、29 件のうち 2 件が期待と違った。**
  - 震源の地名を別の地域に変えた例を通してしまった。震源の地名は震度の文にも出てくるので、「どこかにあるか」だけでは見逃す。「震源」「震央」と同じ区切りに出てくる地域名が震央地名と一致することを求めるように直した。
  - 地域と震度を同じ文の中で入れ替えた例は、止めてはいたが、期待していた「地域ごと」の確認では止まらなかった。文の単位では両方の地域と両方の震度がそろうので、これは照合器の正しい動き。区切り（読点）の単位の「組み合わせ」の確認で止まっていた。期待のほうを直した。
- 思いついた見逃しを 6 つ、照合器にかけた。5 つが通った。そのうち「解除されていません」のような状態の打ち消しは危険なので、打ち消しの言い回しが原文より多いと止める確認を足した。「14:50」の書き方の時刻も、正しい時刻と並べて書かれると通るので、この書き方を止める確認を足した。残りの 3 つ（発表時刻と発生時刻の入れ替え、付加文を残したまま反対のことを足す、緯度と経度の入れ替え）と、電文にない地名は「見逃す例」として残した。
- 最終の結果：正しい例 7 件はすべて通過、誤りの例 32 件はすべて止めた（例ごとに決めた確認で止まった）、見逃す例 9 件はすべて通った。テストは 21 件すべて通った。試作 C-A のテスト 12 件も通った。
- 文書に書いた「止めすぎる」例のうち 2 つ（正しい打ち消し、警報の出ていない地域と「発表した」を同じ文に書く）も、実際に止まることを確かめた。最初は「警報の地域名と同じ文に書くと止まる」と書いていたが、確かめると、止まるのは警報の出ていない地域の場合だった。文書を直した。
- テストの誤り：照合で止めた言い換えが画面に送られないことを確かめるテストで、「安全です」という文字列が送られる内容に含まれていないかを見ていた。誤りの例の説明（「『安全です』と書き…」）に同じ文字列があったので失敗した。テストの対象を電文の欄に絞り、言い換えにしか出ない文字列で確かめるように直した。
- ブラウザ（Playwright）で確かめた。幅 1200 ピクセルで原文と言い換えが左右に並び、各カードの上に発表時刻が出た。幅 375 ピクセルでは上下に並び、横スクロールは出なかった。JavaScript のエラーはなかった。照合器の確認の表では、32 件すべてが「止めた」と出た。
  - 表の「結果」の列が狭く、「止めた」が縦に割れていたので、折り返さないようにした。
  - 止めた理由の中の Python のリストの書き方（角かっこと引用符）がそのまま出ていたので、読点でつなぐ形に直した。
  - スマートフォンの幅では、上の注意書き 3 つで最初の画面が埋まる。試作 C-A と同じ問題で、この回は直していない。
- API の形だけのモード（`--paraphraser api`）で起動すると、言い換えは 1 件も出ず、「API を呼びません」という理由が出ることを確かめた。
- フィードから最新の電文を選ぶ既定の動きも試した（作業用の場所に 3 件）。例文のない電文には「この電文には言い換えの例文がありません」と出て、言い換えは出なかった。
- 秘密情報の検査スクリプトは、コミット前の手動の実行で止まらなかった。**このセッションの個人語の検査は「未実施」だった**（環境変数 ESM_DENYLIST_FILE が未設定）。電文に入っているのは公的な地域名と観測点名で、個人の情報ではないことは人の目で確かめた。

## Claude の使い方（どの機能を何のために）

- **Bash（git）**：フックの設定を表示し、リモートの main との差と、ファイル名が空いているかを確かめた。
- **Bash（curl、python3）**：気象庁のフィードと電文を取得し、構造を確かめた。外から取得したものは作業用の場所に置き、分離モードの Python で読んだ。
- **Write / Edit**：取得・解析・照合器・言い換えの形・サーバー・画面・テスト・例文・文書を書いた。言い換えの例文（正しい例、誤りの例、見逃す例）は Claude Code が電文を読んで書いた。API は呼んでいない。
- **Bash（python3）**：テストと例文の確認を走らせた。思いついた見逃しを、使い捨てのスクリプトで照合器にかけた。
- **Bash（Node.js と Playwright）**：ブラウザで画面を開き、件数・発表時刻・横スクロール・JavaScript のエラーを確かめ、スクリーンショットを撮って見た目を確かめた。スクリーンショットは作業用の場所に置き、リポジトリには入れていない。
- **サーバーの停止**：起動したときのプロセス番号を控えて止めた（s03 の学び）。
- **Hooks**：コミットとプッシュのときに、秘密情報・個人情報の検査が自動で走る。

## 誤り記録

- **Claude の誤り：照合器が震源の地名の取り違えを見逃す作りだった。** 影響は、取り違えた言い換えが通ってしまうこと（画面に出る前に気づいた）。わざと誤りを入れた例を初めて照合器にかけたときに気づき、直した。
- **Claude の誤り：誤りの例の 1 つで、どの確認で止まるかの見込みが違った。** 照合器の動きは正しく、見込みが違っていた。見込みのほうを直し、例の説明にも理由を書いた。
- **Claude の誤り：テストの確かめ方が粗かった。** 止めた言い換えが画面に送られないことを、ありふれた文字列で確かめたため、別の欄の説明文に当たって失敗した。確かめる範囲と文字列を絞った。
- **Claude の誤り：文書に、確かめていないことを確かめたように書きかけた。** 「止めすぎる」例を、実際に照合器にかける前に書いていた。かけてみると、条件が書いた内容と少し違った。文書を直し、確かめていない見逃し（条件の付け方）には「実際には試していない」と書いた。
- **Claude の誤り：サーバーが起動する前に問い合わせた。** API の形だけのモードを確かめるとき、起動を待たずに問い合わせたので失敗した。接続できるまで繰り返し問い合わせる形にして確かめ直した。

## l4b へ戻す学び

- 機械的な照合器を作るときは、**誤りの例と「見逃す例」を先に作り、照合器と一緒に保守する**。今回は、誤りの例で照合器の見逃しを 1 つ見つけ、思いついた見逃しを実際にかけて、さらに 2 つの確認を足せた。見逃す例を「通ることを確かめる」形で残すと、文書の「見逃しうる誤り」が実態とずれない。
- 文字の一致で確かめられるのは、数値・時刻・地域・種類のような「値」の誤り。意味の誤り（反対のことの付け足し、役割の入れ替え、一覧にない言い回しの助言）は止められない。照合を通ったことを「正しい」と言わず、原文を常に並べて出す。
- 照合しやすくするには、言い換えを作る側に書き方の約束を置き、外れたものは「照合できない」として止めるのがよい。照合器を自由な文章に合わせるより確実。
- 文書に「こういう場合に止まる／通る」と書くときは、書く前に実際に照合器にかける。思い込みで書いた条件は、少しずれていた。
