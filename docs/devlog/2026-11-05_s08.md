# 2026-11-05 s08

## 目的

スマートフォンのブラウザで開く簡易なフロントエンドを `app/` に作り、`modules/` のモジュール（センサー、区域、モード、断片、助言の入口）と試作 C-A を 1 枚の画面で組み合わせて見せる。見た目の作り込みは後回しにする。

## 決めたこと（理由・却下した案）

- **画面の論理は `app/lib/` に分け、ブラウザ専用は `app/main.js` だけにした。** 状態の表示名、公的発表のまとめ、モードの保持、表示の文を Node.js の `node --test` で確かめられるようにするため。
- **モジュールは動的な import で読み、失敗したら「未実装」にした。** 1 つが欠けても画面全体が止まらないようにするため。試験のために `?without=` で読み込みを止められるようにした。
- **C-A とは、`app/serve.js`（Node.js の標準ライブラリだけ）の取り次ぎでつなぐ。** C-A に CORS の設定がなく、画面を別のポートから配ると読めないため。取り次ぐのは決まった GET だけで、画面の位置・入力・センサーの値は送らない。却下した案：C-A に CORS のヘッダーを足す案（既存の試作を変えずに済む方を選んだ）。Python で配信する案（依頼の約束で、Python はデータの加工だけに使う）。
- **いったん C-A から受け取ったあとは、模擬データに切り替えない。** C-A の設計（docs/proto/c-a.md）と同じく、本物の途絶を隠さないため。受け取れないときは「古い」と出す。C-A 自身が模擬データで動いているときも、画面は「模擬データ」と出す。
- **C-A の電文は、まだモードの入力につながない。** 電文の種類からモードの `category` への対応は決まっておらず、決めると独自の判断（BW-S1）になる恐れがある。C-A の「警報」の判定がほぼ常に「あり」になる問題もある。モードを動かすのは、申告のボタンと `source: "simulated"` の模擬のボタンだけにし、画面にその旨を書いた。
- **緑色を使わない配色にした（BW-S3）。** 取れたは青、取れない・分からないは橙、古いは赤、未実装は灰。モードの「平常」も灰にした。「平常」には「安全という意味ではありません」、段階の名前「安全確保後」には「安全になったという意味ではありません」を添える。
- **状態の印の文言は、結果の種類ごとに変えた。** センサーは「取れた」、区域は「判定した」、断片は「読み取れた」、公的発表は「受信あり」。断片の読み取り結果に「取れた」と出すと意味が通らないため。
- **緯度・経度は画面に出さない。** 位置の誤差と、引いた市町村・区域だけを出す。画面の写真から位置が漏れないようにするため。
- **位置の許可も、ボタン（位置を取って区域を引く）を押したときに求める。** 開いた直後に許可を求めない。

## 試して分かったこと（失敗を含む）

- Playwright の確認で、C-A から受け取ったときにも「模擬データ」の印が出ていた。印の `display: inline-block` が `hidden` 属性より強く効いていたため。`[hidden] { display: none !important; }` を足して直した。テストの前に目で見た写真では、模擬データのときだけを見ていたので気づかなかった。
- 単体のテストで、断片「5弱」の読み方を数える条件が「読み方が複数あります」の行まで数えていた。テストの条件を直した（画面の不具合ではない）。
- ソースの検査で「緑」の語を探したところ、コメントの「No green」に当たった。CSS のコメントを除いた色の値だけを調べるように直した。
- 本物の C-A（`--source mock`）を `serve.js --ca` で取り次げること、リポジトリの一番上のファイル（CLAUDE.md など）や `..` を含む道筋は配らないことを、手で確かめた。
- テストは 23 件（単体 12 件、Playwright 11 件）すべて通った。Playwright は幅 375 と 1200 ピクセル、明るい表示と暗い表示で、横スクロールがないことと、文字のコントラストが 4.5:1 以上であることを確かめた。
- 揺れと向きのイベント、位置は、すべて Playwright で偽装したもの。実機では確かめていない（確かめる点は docs/proto/app.md）。
- **個人語の検査は未実施。** 環境変数 `ESM_DENYLIST_FILE` が未設定で、フックがそのことを表示した。

## Claude の使い方（どの機能を何のために）

- Bash：既存のモジュールの入出力を Node.js で実際に呼んで確かめてから、画面の部品を作った。
- Playwright（事前に入っていた Chromium）：画面の写真を撮って目で確かめ、そのあと自動の確認に起こした。写真はリポジトリの外の作業用の場所に置いた。
- Git と Claude Code のフック：コミットとプッシュのたびに検査が動いた。
- サブエージェントは使わなかった。

## l4b へ戻す学び

- `hidden` 属性は CSS の `display` に負ける。印や帯の出し分けに `hidden` を使うなら、`[hidden] { display: none !important; }` を最初に入れる。目で見る確認は、出す場合だけでなく「出ない場合」も見る。
- 既存の試作をつなぐとき、同じサイトから配る取り次ぎを置くと、既存の試作を変えずに済む。
