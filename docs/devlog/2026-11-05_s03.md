# 2026-11-05 s03

## 目的

スマートフォンのウェブアプリで使う、センサーごとのモジュールを `modules/sensors/` に作る（位置、揺れ、向き、通信の有無、通信の種類、電池）。画面は作らず、試験用の最小のページだけにする。記録した値の再生で、仮想マシンの中で自動テストできるようにする。実機で確かめるべき点を `docs/proto/sensors.md` に書く。

## 決めたこと（理由・却下した案）

- **ブラウザの機能には `env`（端末とのつなぎ目）を通して触れる。** モジュールが読み込んだ時点でブラウザの機能に触れないので、Node.js でも読み込める。再生の環境（`replay.js`）は同じ形の `env` を作り、`source` を `"simulated"` にする。テストと本番で同じ処理の道筋を通るので、模擬のためだけの分岐がない。却下：モジュールの中で `typeof window` を見て分ける案（再生のときに別の道筋になり、テストの意味が薄くなる）。
- **ブラウザ専用の部分は `demo/` だけにした。** 試験用のページと、ボタンをつなぐスクリプト。
- **`stale` は `read()` のときに判定する。** タイマーで通知する案は、画面がどうせ定期的に読むので要らないと判断した。通信の有無・通信の種類・電池は、`read()` のたびに端末の今の値を読み直すので、ふつうは `stale` にならない（README に書いた）。
- **位置の `stale` は、端末が位置を得た時刻（`timestamp`）で数える。** 受け取った時刻で数えると、端末が持っていた古い位置を新しいとみなしてしまうため。
- **`insecure` は 6 つすべてで返す。** 依頼が「HTTPS でないときは insecure」と一律だったため。通信の有無（`navigator.onLine`）は HTTP でも動くが、扱いをそろえた。
- **許可を求める関数は、ブラウザの `requestPermission()` を同期的に呼ぶ。** iPhone の Safari は、ボタンを押したときの処理の中で直接呼ばないと許可を求めない。間に await があると崩れるので、テストで「戻る前に呼ばれていること」を確かめた。揺れと向きをまとめて求める関数も、2 つを先に呼んでから待つ。
- **揺れ（BW-S1）**：値は生の値だけ。しきい値・判定・通知はない。結果の `value.label` と `detail` に「この端末が記録した揺れ（震度ではありません）」を入れた。テストで、結果の文に「震度」（否定の決まり文句を除く）、「地震」（「地震の有無や強さの判断には使えません」を除く）、警報・速報・避難の語が入らないことを確かめた。重力を差し引く計算はしない（加工すると、加工した値を何かの指標と受け取られやすい）。
- **揺れの最大値は、値がなければ 0 ではなく `unknown`。** 「揺れがなかった」と受け取られないようにするため（BW-S3）。
- **許可の答えが `"prompt"` のときは `unknown`。** 許可されてもいないし、断られてもいないため。
- **記録の仕組み（`recorder.js`）は、既定では位置を記録しない。** 実機の位置は個人の情報なので。位置を含めたときは、記録の説明に「リポジトリに入れない」と書き込む。
- **再生用のデータは、スクリプト（`tools/make-fixture.js`）で作る架空のデータにした。** 位置は経緯度の切りのよい点の近く。揺れは合成した波で、データの説明に「地震の記録ではない」と書いた。疑似乱数の種を固定して、作り直しても同じ中身になるようにした。
- **既定の秒数はすべて「！！仮の値！！」。** 揺れと向き 2 秒、位置 120 秒、位置の取得の待ち 30 秒、揺れの履歴 60 秒、記録の上限 20000 件。実機で決める。

## 試して分かったこと（失敗を含む）

- 自動テストは 50 件、すべて通った（Node.js 22、`TZ=Asia/Tokyo` でも通った）。うち 4 件は Playwright（Chromium）を使うブラウザでの確認。
- Playwright：位置の偽装（架空の座標）、`DeviceMotionEvent` と `DeviceOrientationEvent` の発火、オフラインの切り替え、許可がないとき、HTTP の LAN アドレスで開いたとき（6 つとも `insecure`）、再生（`simulated`）を確かめた。
- **仮想マシンの Chromium は `DeviceMotionEvent.requestPermission()` を持っていた。** iPhone の Safari だけにあると思い込んでいて、最初のテストは「許可は要らない」を期待して失敗した。センサーの許可（加速度計・ジャイロ・磁気）を与えないと `"denied"` か `"prompt"` を返す。テストは、許可を与えた場合と与えない場合の両方を確かめる形に直した。Android の実機でどうなるかは、実機で確かめる点に入れた。
- `about:blank` では `DeviceMotionEvent` 自体がなかった（HTTPS と同じ扱いの画面でないと出ない）。
- Node.js 22 の `node --test` は、ディレクトリを渡すと「モジュールが見つからない」で失敗した。`'test/*.test.js'` のようにパターンを渡す形にした。
- 再生用のデータで、座標を小数 3 桁に丸めたため、位置の小さな動きが消えていた。座標だけ 6 桁にした。
- 実機での確認はしていない（この回ではできない）。確かめるべき点は `docs/proto/sensors.md` に書いた。
- **個人語の検査は未実施。** 環境変数 `ESM_DENYLIST_FILE` が未設定で、コミットとプッシュのたびにフックがそのことを表示した。
- コミットとプッシュのたびに、Git の設定が環境変数で足されているという注意が出た（このクラウドの環境の設定によるもの。止まる検出はなかった）。
- 開発ログの番号：このブランチには 2026-11-05 の s01・s02 の開発ログはない。番号は依頼で指定された s03 にした。

## 誤り記録

- Chromium に `requestPermission()` はないと思い込んで、ブラウザのテストを書いた。テストが失敗して気づき、上のとおり直した。
- 許可を断られたときの説明に、最初「ページを閉じて開き直すと、もう一度求められます」と書いた。確かめていないことを言い切っていたので、「ブラウザを開き直すか、設定を変える必要がある場合があります」に弱め、実機で確かめる点に入れた。

## l4b へ戻す学び

- ブラウザの機能を `env` 越しに使う形にすると、再生（模擬）と本番が同じ処理を通り、Node.js だけで大半を確かめられる。
- 「どのブラウザにどの機能があるか」は思い込まずに、まず実際のブラウザで `typeof` を確かめる。
- 値がないときの結果（最大値の 0 など）は、そのまま「何もなかった」と読まれる。`unknown` として分ける。
