# 2026-11-04 s03

## 目的

試作 C-A を作る。気象庁の防災情報 XML のフィードを定期的に取得し、公的発表を中継しつつ「情報の状態」（最終受信からの経過時間、更新の途絶の可能性、新しい警報の有無）を見せる最小の画面を、Python 3 の標準ライブラリと素の HTML・JavaScript だけで作る。動かし方は `docs/proto/c-a.md` に書いた。

## 決めたこと（理由・却下した案）

- **ブランチ**：依頼では `proto/c-a` だが、この回は実行環境が自動で決めたブランチ（`claude/` で始まる名前）を使った。依頼に「自動で決まる場合はそれで構わない」とあったため。
- **構成**：Python のサーバーがフィードを取得して状態を持ち、画面はそのサーバーに 3 秒ごとに状態を聞く。ブラウザから気象庁を直接読む案は却下した。CORS の可否が未確認で（`docs/research/jma_data.md` の 6）、取得の回数も利用者の数だけ増えるため。
- **「最終受信」と「最終取得」を分けた**：通信は成功しているのに内容が古いまま、という途絶を見逃さないため。途絶の判定は「最終受信」で行う。
- **模擬データへの切り替えは起動時の 1 回だけ**：起動時に実データが取れなければ模擬データにする。いったん実データを受信したあとは、失敗しても模擬データに切り替えない。途中で切り替えると、本物の途絶が模擬データの「受信」で隠れてしまう（BW-S3 の趣旨に反する）。実データと模擬データを混ぜる案も同じ理由で却下した。
- **模擬データは見ればすぐ架空と分かる名前にした**：種類名・地域・官署・本文のすべてに「模擬」と入れた。実在の地域名を使う案は、画面を切り取ったときに本物と見分けられなくなるため却下した。
- **「警報」の判定は種類名の文字列だけで行う**：内容から危険度を推し量ることは BW-S1 に反するため。そのぶん、本番では種類のコードで判定する必要がある（下の「本番にするなら直すべき点」）。
- **途絶のデモは 3 種類**：サーバーの取得失敗、内容が更新されない、画面とサーバーのあいだの途絶。どれも画面に「デモ」と出す。人工的な途絶を本物と取り違えないため。デモ操作は `--demo` を付けたときだけ有効にした。
- **安心を連想させる表示はしない**：緑色や「正常」「異常なし」は使わない（BW-S3）。まだ何も受信していないときは「警報の有無は分かりません」と出す。
- **電文の詳細を取りに行く先を気象庁のホストに限った**：フィードの中のリンクは外部からの入力なので、別のホストや自分のパソコンの中に取りに行かせない。
- **README を更新した**：BW-S2（公的情報の優先を README にも書く）と、外部データの出典を README に書く決まりに合わせた。文言は「！！仮の値！！」。

## 試して分かったこと（失敗を含む）

- セッションの最初に `git config core.hooksPath` を表示した。値は `.githooks` だった。
- 気象庁のフィードへの接続を 1 回だけ試した。前回（s02）と同じく、プロキシに拒否された（403）。s02 の学びに従い、ほかのホストへの試行はしなかった。そのため**実データでは一度も動かしていない**。
- 既定の起動（`--source auto`）で、拒否を受けて模擬データに切り替わり、画面上部に「模擬データ」と出ることをブラウザで確かめた。
- ブラウザ（Playwright）で次を確かめた。
  - 通常時に「新しい警報は受信していません。安全という意味ではありません。」が出る。
  - 模擬の警報電文を入れると、件数とその電文の一覧に切り替わる。
  - 取得失敗の途絶で、経過時間が延び続け、しきい値を超えると「更新が途絶えている可能性」が上部と本文に出る。警報の欄にも「受け取れていないだけかもしれない」と添えられる。
  - 内容が更新されない途絶で、エラーは「なし」のまま途絶の表示が出る。
  - 画面側の受信を止めると、「この画面はサーバーから状態を受け取れていません」と「（デモ）」が出る。
  - 幅 375 ピクセルで横スクロールが出ない。JavaScript のエラーはなかった。
- 最初の版では、模擬データの帯に切り替えの理由（通信エラーの全文）まで入れていた。スマホの幅では帯が長くなりすぎて本文が隠れたので、帯は短い一文にし、理由はページ下の注記に移した。
- 帯が 3 つ（模擬データ・デモ・途絶）同時に出ると、スマホの幅で画面の 3 分の 1 ほどを占める。試作ではそのままにした。
- テストを 11 件書き、すべて通った（解析、模擬データ、警報の新着、2 種類の途絶、実データの失敗で模擬データに切り替わらないこと、詳細の取得先の制限）。
- **このセッションの個人語の検査は「未実施」だった**（環境変数 ESM_DENYLIST_FILE が未設定）。個人語の確認は人の目に頼った。

## 良かった点

- 「情報の状態」を、受信の状態・警報の新着・最新の発表の 3 つに分けて見せられた。特に「通信は成功しているのに内容が古い」途絶を、エラーなしの状態のまま途絶として示せた。
- 経過時間をブラウザの側でも数え続けるので、サーバーが止まっても画面が「古いまま静かに正常そうに見える」ことがない。
- 模擬データとデモの途絶が、画面のどこを切り取っても本物と取り違えにくい。
- 外部ライブラリなしで、起動 1 行で動く。

## 本番にするなら直すべき点

- **実データで確かめる**：フィードの URL、電文の要素の名前（発表時刻・情報の種類・対象地域・運用種別）は未確認の想定のまま。ネットワークの許可をもらい、`docs/research/jma_data.md` の手順で確かめてから作り直す。
- **「訓練」「試験」の電文を除外する**：いまは印を付けて表示するだけ。本番の画面には出さない処理が要る（BW-S1）。
- **「取消」「訂正」を扱う**：いまは情報の種類を文字列で表示するだけで、取り消された電文を打ち消していない。
- **「警報」の判定を種類のコードで行う**：種類名の文字列で判定しているため、「警報級」のような語にも反応する恐れがある。
- **対象地域を正しく出す**：いまは見出し部分の地域名を抜き出しているだけで、警報の本文にある地域ごとの状態（発表・継続・解除）は読んでいない。「解除」を受け取っても「安全」と出さない設計も必要（BW-S3）。
- **XML の解析を安全にする**：標準ライブラリの XML 解析を使っている。外部からの XML を読むので、本番では悪意のある XML への対策が確かなものに替える。
- **途絶のしきい値を決める**：既定の 600 秒は仮の値。フィードの実際の更新間隔と、気象庁が求める取得の頻度を確かめてから決める。フィードごとに分ける必要もありそう。
- **取得の作法を確かめる**：前回の取得時刻を送って変わっていなければ中身を受け取らない仕組み（条件付き取得）は入れたが、気象庁がどう求めているかは未確認。
- **状態を保存する**：サーバーを再起動すると、受信の記録がすべて消える。
- **公開の仕方**：いまは自分のパソコンだけで見る前提。人に見せるなら、デモ操作を外し、アクセスの制限、HTTPS、負荷を考える。
- **画面**：帯が重なるとスマホで本文が隠れる。文言（公的情報の優先、途絶の表示）は「！！仮の値！！」のまま。読み上げ（スクリーンリーダー）で状態の変化が伝わるかも確かめていない。
- **出典の表示**：利用条件（`docs/research/jma_data.md` の 5）を読んでから、出典と加工の表示の書き方を決め直す。

## Claude の使い方（どの機能を何のために）

- **Bash（curl）**：気象庁のフィードに接続できるかを 1 回だけ確かめた。
- **Write / Edit**：サーバー、画面、テスト、ドキュメントを書いた。
- **Bash（python3）**：テストを走らせ、サーバーを起動した。
- **Bash（Node.js と Playwright）**：ブラウザで画面を開き、デモのボタンを押して表示の切り替わりを確かめ、スクリーンショットを撮って見た目を確かめた。スクリーンショットは作業用の場所に置き、リポジトリには入れていない。
- **Hooks**：コミットのときに秘密情報・個人情報の検査が自動で走る。

## 誤り記録

- **Claude の誤り：テスト用サーバーを止めるコマンドで、自分のシェルごと止めた（2 回）。** プロセスの名前の一部で探して止める方法を使ったところ、そのコマンドを実行しているシェル自身の文字列にも一致した。影響は、そのときのコマンドが途中で終わっただけ（終了コード 144）。2 回目に同じ種類の誤りを繰り返したあと、先頭が `python3` のプロセスだけに絞る形に直し、さらに起動したプロセスの番号を覚えて止める形にした。
- **Claude の誤り：作業用のスクリプトのファイルが作られていなかった。** 上の誤りでシェルが途中で止まり、ファイルを書く部分が実行されていなかったのに、続けてそのファイルを実行しようとした。エラーで気づき、ファイルを書き直した。

## l4b へ戻す学び

- 起動したプロセスを止めるときは、名前で探さずに、起動したときのプロセス番号で止める。名前で探すと、探しているコマンド自身にも一致することがある。
- 「途絶」には少なくとも 3 つの形がある（取得の失敗、内容が古いまま、画面とサーバーのあいだ）。エラーが出ない途絶もあるので、通信の成否ではなく「内容が新しくなったか」で判定する。
- 代わりのデータ（模擬データ）への自動切り替えは、本物の障害を隠す。切り替えるのは起動時だけにして、切り替えたことを常に表示する。
