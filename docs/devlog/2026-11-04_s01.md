## 決めたこと（理由・却下した案）

- **bash と git だけで実装する。** 正規表現は bash の `[[ =~ ]]` を使い、`grep` や `tr`、`dirname` などの外部コマンドを使わない。
  - 却下：gitleaks などの外部ツール（今回の条件で使わない）。jq で JSON を読む案（標準にないため。Claude Code のフック入力は bash の正規表現で `command` だけを取り出す）。
- **検出パターンは断片をつないで組み立てる。** スクリプト自身を検査しても引っかからない。ファイル単位の除外はしない。
- **追加された行だけを検査する。** 削除行や前後の行は見ない。push のときはコミットを 1 つずつ見る。後のコミットで消した秘密も履歴には残るので止める。
- **出力では一致した値を伏せる。** 先頭 2 文字と長さだけを出す。個人語は「禁止語リストの何行目か」だけを出し、語そのものは出さない。検査結果のログから漏れるのを防ぐため。
- **`.env` は `.env.*` も止める（`.env.example` だけ許可）。** `.gitignore` の扱いに合わせた。
- **禁止語ファイルがリポジトリ内にあるときは止める。** 誤ってコミットされるのを防ぐため。未設定、ファイルがない、中身が空のときは止めずに「個人語の検査は未実施」と必ず表示する。
- **メールアドレスは、ドメインが次のどちらかなら許可する。** GitHub の noreply ドメインそのもの。example ドメインそのものか、そのサブドメイン。似ているだけの別ドメインは止める。
- **検査が正しく動かなかったときは止める側に倒す（fail closed）。** 終了コードはすべて 2。Claude Code のラッパーも、0 以外を受け取ったら 2 で止める。
- **Claude Code のフックが通ったときも結果を伝える。** `systemMessage`（利用者向け）と `additionalContext`（Claude 向け）で「未実施」を伝え、黙って通さない。
- 却下：Git の pre-push フックの追加（依頼の範囲外。「次にやること」に回した）。

## 試して分かったこと（失敗を含む）

- 一時リポジトリで単体テストをした。偽の値はシェルで断片をつないで、その場で作った。
  - 止まることを確認：Anthropic・AWS（アクセスキー ID、シークレット）・GitHub（従来型、fine-grained）のキー、秘密鍵の開始行、許可していないメールアドレス、`.env`・`.env.local`・`*.pem`（大文字も）・`.claude/settings.local.json`・`CLAUDE.local.md`
  - 止まらないことを確認：`.env.example`、許可ドメインのメールアドレス
  - 警告のみで終了コード 0：UUID
  - 個人語：大文字小文字を区別せずに一致した。日本語も一致した。CRLF、空行、`#` 行も正しく扱えた。リポジトリ内に置いたファイルは止めた。未設定、ファイルなし、空ファイルでは「未実施」と表示した。
  - push モード：途中で入れて後で消したメールアドレスも止めた。リモートにすべてあるときは 0 件で通った。
  - スクリプト自身をステージしても検出 0 件だった。
- **検証 1（偽キーでコミットが止まるか）：** 本番リポジトリで偽の Anthropic 形式のキーをテスト用ファイルに書き、`git add` してから `git commit` した。
  - 1 回目（`git add` と `git commit` を同じコマンドで実行）：Claude Code の PreToolUse フックは `git add` より前に動くので、ステージは空で通った。そのあと Git の pre-commit フックが止めた。
  - 2 回目（ステージ済みの状態で `git commit` だけを実行）：PreToolUse フックが止めた（終了コード 2）。
  - 確認したあと、テスト用ファイルはステージから外して削除した（コミットしていない）。
  - 分かったこと：PreToolUse の検査は「コマンドを実行する前の状態」しか見られない。最後の守りは Git の pre-commit フック。この点を CLAUDE.md に書いた。
- **検証 2：** どの実行でも「個人語の検査は未実施（環境変数 ESM_DENYLIST_FILE が未設定）」と表示されることを確認した。
- **このセッションの個人語の検査は「未実施」だった**（ESM_DENYLIST_FILE が未設定）。個人語の確認は人の目に頼った。
- `.claude/settings.json` を作ると、このセッションの途中から PreToolUse フックが有効になった。テスト用のコマンドに `git commit` や `git push` の文字列が入っているだけでも、本番リポジトリの検査が走った。
- SessionStart フックと同じ `git config core.hooksPath .githooks` を手で実行して、pre-commit フックを有効にした。
- **検証 3（作成者メールアドレス）：** コミットする前に `git var GIT_AUTHOR_IDENT` で、作成者が noreply アドレスになることを確認した。コミットしたあと、プッシュする前にもう一度確認する（結果は最終報告に書く）。

## Claude の使い方（どの機能を何のために）

- **Claude Code（クラウドのセッション）：** スクリプトとドキュメントを作り、テストし、コミットまで行った。
- **WebFetch：** Claude Code のフックの公式ドキュメントで次の点を確かめた。
  - PreToolUse の終了コード 2 で実行が止まり、標準エラーが Claude に渡ること
  - 終了コード 0 の場合は標準エラーが Claude に届かないこと
  - `additionalContext` と `systemMessage` が使えること
  - `CLAUDE_PROJECT_DIR` が使えること
- **Hooks（PreToolUse・SessionStart）：** コミットとプッシュの前の自動検査に使った。自分のコミットにもこの検査がかかった。
- **一時ディレクトリ：** 本番リポジトリを汚さずに、偽キーで単体テストをした。

## 誤り記録

- 最初の版のスクリプトで、`tr`・`dirname`・`basename` を使っていた。「bash と git の標準機能だけ」という条件に合わないので、bash のパラメータ展開に置き換えた。見直しの段階で気づいた（テストの前）。
- 最初の版では、push モードの `commit` 行を判定する条件を複雑にしすぎていた。差分の本文の行には必ず 1 文字の接頭辞が付くので、単純な判定で足りると分かり、書き直した。

## l4b へ戻す学び

- 「コマンドを実行する前」のフックには限界がある。`add && commit` のように 1 回でまとめたコマンドの中身は、実行前には見えない。守りを 1 か所に頼らず、Git 側のフックと重ねる。
- 検査スクリプトは、自分自身や検査結果のログから秘密を漏らしやすい。パターンは断片をつないで書く。一致した値は出力で伏せる。
- 「止めない」ときも、黙って通さない。未実施であることを人にも Claude にも見える形で出す。
